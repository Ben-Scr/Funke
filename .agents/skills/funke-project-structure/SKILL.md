# Funke Game Project Structure

Everything here describes a **game project folder** (what the Launcher creates and the Editor opens), not the Funke engine source tree. The authority is `Funke-Engine/src/Project/FunkeProject.cpp` (`FunkeProject::Create`, `BuildProjectJson`, `Load`, `ResolvePaths`, `CreateDirectoryTree`).

## The folder tree

`FunkeProject::Create` scaffolds exactly this:

```
<ProjectRoot>/
├── project.json                 # project config (see schema below)
├── <Name>.csproj                # the game's C# script assembly (SDK-style, net10.0)
├── <Name>.sln                   # VS solution wrapping the .csproj
├── .gitignore                   # bin/ obj/ .vs/ *.user NativeScripts/build/ Packages/
├── .vscode/settings.json        # OmniSharp + dotnet.defaultSolution
│
├── Assets/                      # ALL game-authored content (the .csproj globs Assets\**\*.cs)
│   ├── Scripts/                 # starter scripts live here (GameScript.cs); .cs may live anywhere under Assets/
│   │   └── GameScript.cs        # scaffolded starter EntityScript
│   ├── Scenes/                  # .scene files (SampleScene.scene scaffolded)
│   │   └── SampleScene.scene
│   └── …                        # your sprites (.png/.jpg…), audio (.wav…), fonts (.ttf), prefabs, dataassets — each with a .meta sibling
│
├── FunkeAssets/                 # engine-shipped assets copied into the project (default font, default textures…)
├── Packages/                    # installed packages + a copy of Funke-ScriptCore (GIT-IGNORED)
│   └── Funke-ScriptCore/        # Funke-ScriptCore.dll + .pdb (the scripting API you reference)
├── NativeScripts/               # optional C++ native-script project
│   ├── CMakeLists.txt           # generated
│   └── Source/                  # your .cpp native scripts
├── BuildProfiles/               # one .build file per build profile (see funke-build-and-ship)
└── bin/                         # compiled C# assembly output: bin/<Config>/<Name>.dll  (GIT-IGNORED)
```

Path members (from `ResolvePaths`): `AssetsDirectory = Assets`, `ScriptsDirectory = Assets/Scripts`, `ScenesDirectory = Assets/Scenes`, `FunkeAssetsDirectory = FunkeAssets`, `PackagesDirectory = Packages`, `NativeScriptsDir = NativeScripts`, `NativeSourceDir = NativeScripts/Source`, build profiles at `BuildProfiles`.

**Critical gotchas:**
- **`Packages/` is git-ignored** — including the bundled `Funke-ScriptCore.dll`. A fresh clone has no scripting DLL to reference until the Editor re-runs `ConfigurePackages` (it re-copies on open). Don't be surprised the `.csproj` reference is "missing" right after clone.
- **Keep `.meta` files; commit them.** Every asset has a `<file>.meta` holding its permanent GUID + import settings. Lose it and references break. → `funke-assets-and-content`.
- **`bin/` and `obj/` are build output**, regenerated by `dotnet build`. Don't author there.

## `project.json` schema

Written by `BuildProjectJson`, read by `Load`. Field names are exact. (Defaults shown are the C++ member defaults.)

```jsonc
{
  // Identity
  "name": "MyGame",
  "engineVersion": "…",              // FNK_VERSION at create time

  // Scenes
  "startupScene": "SampleScene",     // scene loaded first at runtime
  "lastOpenedScene": "SampleScene",  // editor convenience
  "buildScenes": ["SampleScene"],    // scenes that SHIP (authoritative; unlisted scenes don't load at runtime)

  // Global C# systems instantiated at startup (persist across scene loads)
  "globalSystems": [
    { "className": "GameManager", "active": true }
    // legacy string form ["GameManager"] is also accepted (implies active=true)
  ],

  // Editor game-view
  "gameViewAspect": "16:9",
  "gameViewVsync": true,

  // Build window (the shipped game's window)
  "buildWidth": 1920, "buildHeight": 1080,
  "buildMinWidth": 0, "buildMinHeight": 0, "buildMaxWidth": 0, "buildMaxHeight": 0,
  "buildFullscreen": true,
  "buildFullscreenMode": "Exclusive",     // Exclusive | BorderlessWindowed | Maximized
  "buildResizable": true,
  "buildRunInBackground": true,
  "buildAspect": "Free Aspect",

  // Executable & branding
  "executableName": "",                   // empty → derive from name + platform ext
  "buildVersion": "1.0.0",
  "buildCompany": "",
  "appIcon": "",                          // project-relative path to icon image

  // UI canvas reference resolution
  "uiReferenceWidth": 1920, "uiReferenceHeight": 1080,
  "uiScaleMode": "MatchWidthOrHeight",    // or "Fit" (whole reference always visible) / "Fill" (covers screen)
  "uiScaleMatch": 0.5,                    // MatchWidthOrHeight only: 0=match width, 1=match height
  "cursorImagePath": "",
  "uiInteractableCursorImagePath": "",

  // Splash screen
  "splashScreen": {
    "enabled": true, "durationSeconds": 0.7, "fadeInSeconds": 0.5, "fadeOutSeconds": 0.0,
    "imagePath": "", "backgroundImagePath": "", "customText": "",
    "backgroundR": 0.05, "backgroundG": 0.05, "backgroundB": 0.07,
    "fontColorR": 1.0, "fontColorG": 1.0, "fontColorB": 1.0, "fontSize": 16.0
  },

  // Packages allow-list (see funke-author-package). Empty/absent has specific fail-closed semantics there.
  "packages": [],

  // Engine modules ("Funke.2D", "Funke.3D"; none = UI-only app). Absent = both. The editor offers only these
  // modules' components; builds ship a runtime compiled without the others and refuse scenes that use them.
  // Only "Funke.3D" opens the Editor View in 3D mode. Edited via Package Manager > Engine Modules or
  // `funke package add|remove Funke.3D`; installing a package whose manifest lists `modules` adds them. See Github-Docs/Documentation/Engine-Core/Engine-Modules.md.
  "modules": ["Funke.2D"],

  // Runtime behavior
  "showRuntimeStats": true,               // FPS / frame-time overlay in shipped build; omit = on for Development, off for Release
  "showRuntimeLogs": true,                // log console in shipped build; omit = same as above
  "enablePostProcessing": true,

  // Serialization & ECS
  "assetSerializationFormat": "Json",     // Json | Binary — applies to .scene/.prefab/.dataasset
  "entityBits": 20,                       // 16|20|22|24|28 → max 2^N-1 entities

  // Build profile & rendering (see funke-build-and-ship)
  "activeBuildProfile": "",               // active named profile
  "buildProfile": "Development",          // Development | Release
  "renderBackend": "Auto",                // Auto|Vulkan|Direct3D11|Direct3D12|OpenGL|Metal|OpenGLES
  "customDefines": [],                    // extra #define constants baked into the C# assembly

  // Default font asset GUID (as a uint64 string)
  "defaultFontAsset": "…",

  // Optional profiler block in shipped builds
  "profiler": { "enableInRuntime": false, "trackInBackground": false, "samplingHz": 60, "trackingSpan": 200, "modules": {} },

  // Editor-only naming rules
  "editorEnsureUniqueEntityNames": true,
  "editorEntityNameSuffix": "ParenthesizedNumber"  // SpaceNumber|ParenthesizedNumber|HyphenNumber|UnderscoreNumber
}
```

Scene/startup names are validated (`IsValidSceneName`): no leading `.`, no path separators / `:`, no `..`, no shell metacharacters.

## The game's C# script assembly

`<Name>.csproj` is generated verbatim by `Create`. Don't hand-edit the generated parts; the Editor rewrites it.

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Library</OutputType>
    <TargetFramework>net10.0</TargetFramework>
    <Configurations>Debug;Release;Dist</Configurations>
    <AllowUnsafeBlocks>true</AllowUnsafeBlocks>
    <EnableDynamicLoading>true</EnableDynamicLoading>
    <CopyLocalLockFileAssemblies>true</CopyLocalLockFileAssemblies>
    <EnableDefaultCompileItems>false</EnableDefaultCompileItems>
    <EnableDefaultNoneItems>false</EnableDefaultNoneItems>
    <Nullable>enable</Nullable>
    <AppendTargetFrameworkToOutputPath>false</AppendTargetFrameworkToOutputPath>
  </PropertyGroup>
  <!-- per-config OutputPath: bin\Debug\ | bin\Release\ | bin\Dist\ (Release/Dist Optimize=true) -->

  <ItemGroup>
    <Compile Include="Assets\**\*.cs" />          <!-- ALL .cs under Assets/, not just Assets/Scripts -->
  </ItemGroup>

  <ItemGroup>
    <Reference Include="Funke-ScriptCore">
      <HintPath>Packages\Funke-ScriptCore\Funke-ScriptCore.dll</HintPath>
      <Private>true</Private>
    </Reference>
  </ItemGroup>

  <Import Project="Packages/FunkePackages.props" Condition="Exists('Packages/FunkePackages.props')" />
  <Import Project="Packages/FunkeDefines.props" Condition="Exists('Packages/FunkeDefines.props')" />
</Project>
```

Key facts:
- **Target:** `net10.0`, output `Library`. Assembly = `<Name>.dll` in `bin/<Config>/`. Visual Studio IntelliSense requires Visual Studio 2026 (18.0+) for this target; VS2022 remains usable for the native v143 solution only.
- **Compile glob is `Assets\**\*.cs`** — you can put scripts anywhere under `Assets/`, not only `Assets/Scripts/`. (Older projects globbed `Assets\Scripts\**` and are auto-migrated on open.)
- **Scripting API reference** is a plain DLL `<Reference>` to `Packages\Funke-ScriptCore\Funke-ScriptCore.dll` (copied in on create/open by `ConfigurePackages`) — **not** a NuGet/ProjectReference. This is what gives you `EntityScript`, `SceneSystem`, `GlobalSystem`, `DataAsset`, `Input`, `Time`, etc.
- **Three configs:** `Debug` / `Release` / `Dist` (Dist = optimized, no symbols, shipped).
- **Two auto-generated imports:** `Packages/FunkePackages.props` (managed by the package installer) and `Packages/FunkeDefines.props` (regenerated on every save: `FUNKE_EDITOR` vs `FUNKE_BUILD`, build-profile defines, platform define, and your `customDefines`). Don't edit these by hand. (See `funke-build-and-ship` for what the defines mean.)

## Scene & prefab files

`.scene` / `.prefab` / `.dataasset` are serialized as **JSON** in new projects (`FunkeProject::Create` writes `assetSerializationFormat: "Json"`), or **Binary** if the project uses that setting — a `project.json` without the key reads as Binary (older projects). `funke convert --format json|binary` switches a project. JSON is what you reason about; binary is the same data in a compact `FNKSCNB`-tagged container.

The scaffolded `SampleScene.scene` in JSON form is exactly:

```json
{
  "version": 1,
  "name": "SampleScene",
  "systems": [],
  "entities": [
    {
      "name": "Camera",
      "Transform2D": { "posX": 0.0, "posY": 0.0, "rotation": 0.0, "scaleX": 1.0, "scaleY": 1.0 },
      "Camera2D": { "orthoSize": 5.0, "zoom": 1.0 }
    }
  ]
}
```

A scene file holds: a format `version`, the scene `name` (+ id), a `systems` array (C# `SceneSystem` class names, resolved by simple class name; plus saved settings), and an `entities` array. Each entity carries its components as named members (`Transform2D`, `SpriteRenderer`, `Rigidbody2D`, `BoxCollider2D`, …), script field values, and parent/child hierarchy.

Important behaviors:
- **Only authored entities are saved.** Entities you spawn at runtime (`Entity.Create`, `Instantiate`) vanish on scene reload — by design.
- **Round-trip is exact.** What you save is what you load.
- **Asset references are GUIDs**, never paths (resolved via `.meta`).
- A **prefab** is a saved entity tree (`.prefab`); instances track their source prefab and may carry per-instance overrides.

### `.meta` files

One JSON sidecar per asset, holding the stable `AssetGUID`/`uuid` and the asset `kind` (+ import settings like texture filter/wrap and sprite slices). Generated on first discovery if missing — **but a regenerated `.meta` gets a NEW GUID, breaking old references.** Always move/commit `.meta` alongside its asset.

## How scenes register at runtime

The Runtime (`Funke-Runtime`, `RuntimeApplication::ConfigureScenes`) reads `project.json` and:
1. For each name in `buildScenes`, calls `RegisterScene(name)` and attaches an `OnLoad` callback that `SceneSerializer::LoadFromFile`s the resolved `.scene` path (format auto-detected from the file's magic bytes).
2. Marks the `startupScene` as the startup scene (falling back to `lastOpenedScene`, then `"SampleScene"`). If the startup scene isn't in `buildScenes`, it's registered anyway.
3. Only the startup scene auto-loads; the rest load on demand via `SceneManager` (from C#: `SceneManager.LoadScene("Name")` — see `funke-game-scripting`).

So `buildScenes` is the authoritative ship list: a scene file that exists on disk but isn't listed won't be loadable in the built game.

## Creating / duplicating a project

`FunkeProject::Create(name, parentDir[, directoryName])` runs: create dir tree → copy `Funke-ScriptCore.dll/.pdb` into `Packages/Funke-ScriptCore/` → write default build profiles → copy engine `FunkeAssets/` → write `project.json` → write starter `SampleScene` → write `<Name>.csproj` + `.sln` → write starter `Assets/Scripts/GameScript.cs` → write `.vscode/settings.json` → generate native-script CMake files → write `.gitignore`. `Duplicate(...)` deep-copies with GUID remapping. Humans normally trigger this from the **Launcher**.

`Create(name, parentDir, directoryName, const ProjectTemplate*, progress)` uses a project template instead of the built-in starter: the template's `Assets/` replaces the starter scene and scripts (scenes converted to the project format, `{{ProjectName}}` / `{{ProjectIdentifier}}` expanded) and its `modules` go into `project.json`. Templates live in `<engine root>/templates/<Id>/template.json` (`Funke.Empty2D`, `Funke.Empty3D`) and in `%LOCALAPPDATA%/Funke/Templates` (user templates from `ProjectTemplates::CreateFromProject`, the Launcher's **Save as Template...** / Templates page; `UpdateUserTemplate` and `RefreshFromSourceProject` edit them, `FUNKE_USER_TEMPLATES_DIR` overrides the folder for tests). A template's optional `project.json`, `BuildProfiles/`, `NativeScripts/Source/` and `Packages/<local>/` carry settings, profiles, native scripts and local packages into new projects; see `Project/ProjectTemplate.hpp`.

The scaffolded `GameScript.cs`:

```csharp
using Funke;

public class GameScript : EntityScript
{
    public override void OnStart()
    {
        Log.Info("Hello from <Name>!");
    }

    public override void OnUpdate()
    {
    }
}
```
