# Entity creation optimization — 13 November 2026

The changes reduce C# ECB recording overhead. Native staged creation also reuses handle and identity vectors, but the measurements do not establish an overall native-playback speedup. The public API, wire format, playback selection thresholds, and callback behavior are unchanged.

## Recording measurements

Release, .NET 10, tiered compilation and ReadyToRun disabled. Two components per entity; 100,000 entities. Each result is the median of three process medians, with ten warmups and 31 samples per process. Run order was reversed for the second pair. No compilation ran during these final measurements.

The native callback in this harness is a stub. These figures cover command recording, including scheduling in the worker rows; they are **not complete entity-creation times**. Wire assembly/playback is timed separately in the raw JSON.

| Recording case | Before (ms) | After (ms) | Speedup |
|---|---:|---:|---:|
| Single-thread CreateWith | 1.0224 | 1.0271 | 1.00× |
| ParallelWriter on one thread | 2.5563 | 1.1360 | 2.25× |
| ParallelWriter, four workers | 0.6591 | 0.3096 | 2.13× |
| Single-thread payload commands | 1.6049 | 1.4913 | 1.08× |
| Payload writer on one thread | 3.2457 | 2.2095 | 1.47× |
| Payload writer, four workers | 0.8377 | 0.5592 | 1.50× |
| Bulk defaults, one thread | 1.0070 | 0.1279 | 7.87× |
| Bulk defaults, four workers | 0.6571 | 0.0498 | 13.19× |

The unchanged single-thread default loop is a control. At 10,000 entities, bulk recording measured approximately 0.1015 → 0.0126 ms on one thread. Scheduling and merging still impose costs on small parallel batches.

## Native playback

The real engine benchmark includes scene entity allocation, identity registration, component construction, and notifications. Recording and destruction are outside timing. Each process runs three warmups and fifteen samples per case, with three alternating before/after process pairs. Four native workers are available.

| 100,000 entities | Before (ms) | After (ms) |
|---|---:|---:|
| Defaults, sequential | 26.0101 | 25.9576 |
| Defaults, parallel | 10.3415 | 10.2546 |
| Defaults, automatic | 10.4876 | 10.4733 |
| Payloads, sequential | 27.6375 | 27.8690 |
| Payloads, parallel | 15.0194 | 15.3154 |
| Payloads, automatic | 15.1986 | 15.3592 |

These native changes are within workload/run variation; no native percentage improvement is claimed. At 1,000 default entities, forced-parallel medians were 0.1124 → 0.1459 ms, but individual before/after process medians overlap (roughly 0.10–0.15 ms). Automatic mode remained about 0.107 ms. Native scratch reuse removes two per-batch vector allocations at the cost of retaining high-water capacity (about 1.2 MB for handles and IDs at 100,000 entities); nested playback uses independent scratch.

## Implementation and verification

- The parallel recorder uses a weak per-thread slot cache, avoiding repeated dictionary lookups without retaining abandoned or disposed recorders. CreateWith resolves the slot once per entity.
- All eight CreateEntitiesWith arities resolve types and reserve capacity once, then write the command stream directly. Length and overflow checks happen before recording.
- Component-reference validation keeps exception construction out of the hot path; payload-size checks can be eliminated for ordinary fixed-size component types.
- 122 native ECB/entity test cases passed (2,916,323 assertions), covering creation, identity collisions, callbacks, fallback, nested playback, and destruction. All six final native benchmark processes also passed.
- 28 managed ECB cases passed, including every bulk arity, reference remapping, payload limits, Clear/reuse, worker isolation, and disposal/GC on live threads. The compiled xUnit Fact/InlineData cases were executed sequentially through a direct reflection runner because VSTest did not complete in this environment.
- Building the full managed test project required temporarily excluding the existing ManagedComponentStoreTests.cs, which still references the removed Entity.Transform property. That file was not edited.
- Engine, EngineTests, and ScriptCore built successfully for the measured binaries. A later whole-engine build encountered an unrelated concurrent Renderer2D/SpriteDrawBundle::PassKey deleted-equality-operator error. The tested ECB changes remain as validated; no unmeasured additional native optimization was retained.
