Funke ECS: C# ScriptCore vs native C++ NativeScript
Ryzen 9 7900X, 12 cores / 24 threads, 32 GiB DDR5-6000; Release x64; 16 engine workers.
3 warmups, 9 measured samples/run; medians in ms; all PASS.
Release x64; native DLL loaded as NativeScript; C# SceneSystem; same frozen engine/runtime; one persistent driver entity; Transform2D + SpriteRenderer default components; setup, validation, cleanup and ECB entity-wrapper materialization excluded; sequential recording and explicitly parallel shared-backend playback; direct timings include public API costs.
Public native ECB Create2 uses its own sequential implementation. NativeWireParallel is an internal shared-backend control, not a public native ECB API. Compare PlaybackMs for this control.
Direct APIs have different identity, wrapper, dependency and cache costs; results are not a pure language-speed ratio.
Driver survives destruction; previous whole-scene destroy measurements are not directly comparable.
Separate process runs on a desktop machine; timing differences include allocator, cache, GC and scheduler variation.
C# direct native-component calls resolve UUID to scene/handle and use the generic ComponentInfo dispatch; native Entity retains registry and handle.
C# Add additionally uses AddWithDependencies, including module and conflict checks. Native typed Add uses ComponentUtils and typed emplace. The fixture has no conflicts or missing dependencies.
C# typed Remove passes notifyManaged=false into native code and invalidates its wrapper cache locally. There is no reverse native-to-managed callback for this direct path.
These call-chain differences do not attribute time to individual causes; that would require profiling. The comparison covers these structural operations, not general C++ versus C# execution speed.
