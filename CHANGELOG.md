# Changelog

Release notes describe user-visible compatibility, reliability, and workflow changes. A public tag is accepted only when its exact version has a section here.

## [2026.1.0-beta.1]

First public beta. The editor runs on Windows x64, Linux x64 and macOS (Apple Silicon and Intel); each exports games for its own desktop platform, and to Android, iOS and Web through platform packages. See `Github-Docs/Documentation/Known-Limitations.md`.

### New

- **Editor, Launcher and `index` tool on Linux and macOS:** the whole toolchain builds and runs natively on Linux x64 and on macOS (arm64 and x64), and release bundles for both are produced alongside the Windows one. The C# projects build through `dotnet` (`Index-Managed`), project and engine packages build with `make`, and **Rebuild Engine** (entity bits) opens a terminal with a `make` build instead of a console with MSBuild. Build, import and package progress shows in an in-editor window; "Show in Explorer" becomes **Reveal in Finder** / **Show in File Manager** (with the file selected on desktops that support it). Crashes write a `<app>-<time>.crash.txt` with a backtrace to the crash dump folder. Missing tools are offered through Homebrew on macOS, and distribution-built .NET SDKs (Ubuntu, Fedora) are recognised.
- **Linux and macOS game exports:** the Linux editor exports a Linux folder (executable plus its libraries), the macOS editor a signed-ad-hoc `<Name>.app` with `Info.plist`, `AppIcon.icns` and the content in `Contents/Resources`. From a source checkout the runtime is compiled fresh with `make`, like MSBuild does on Windows. New projects get a `macOS` build profile next to `Windows` and `Linux`, and new profiles default to the editor's own platform.
- **Triggers:** colliders with **Sensor** enabled now raise `OnTriggerEnter2D`, `OnTriggerStay2D` and `OnTriggerExit2D` (previously sensor overlaps were never reported). `Collision2D.IsTrigger` tells the two apart.
- **Streaming audio from any file:** `AudioStream.Open(path)` plays MP3, WAV or FLAC files outside the project (a music folder, downloads) straight from disk, with `Play/Pause/Stop`, seeking via `Time`, `Length`, `IsAtEnd`, `Volume` and `Loop`. Leaving Play mode closes every open stream.
- **Mouse wheel in scroll views:** the wheel now scrolls a list while the cursor is over one of its rows. It used to react only when the scroll view itself was under the cursor, so lists of buttons only scrolled in the gaps between them. A vertical list wins over a horizontal carousel inside it; multiline input fields keep scrolling their own text.
- **Input fields on phones:** tapping outside a focused field (on a button, a list or empty space) now closes the keyboard; the field used to grab focus back the next frame. Holding a finger on the text selects a word and opens Android's Cut / Copy / Paste / Select all toolbar; dragging selects a range. Password fields no longer allow copying their text, also with Ctrl+C on the desktop.
- **Media controls for music apps:** `MediaSession` shows a Spotify-style "now playing" notification on Android (cover, title, artist, previous / play-pause / next, seek bar), with the same controls on the lock screen and for headset buttons. Scripts publish the track with `SetNowPlaying`, the state with `SetPlaybackState`, and read button presses with `TryGetCommand`. Needs `Audio.PlayInBackground` and the Android build option `backgroundAudio`.
- **Decoding images at runtime:** `Texture.DecodeImage(bytes, maxSize, out w, out h)` turns PNG/JPEG/BMP/TGA bytes (e.g. cover art inside an MP3) into RGBA pixels, shrunk to `maxSize`, and is safe on worker threads; `Texture.Create(w, h, pixels)` makes a texture from them.
- **Android UI uses the full screen width:** the safe area no longer subtracts the back-gesture zones at the left and right edge, which squeezed full-width UI by about 150 px on phones with gesture navigation. Only the status bar, navigation bar and camera cutout count.
- **Android games no longer run out of memory on Mali GPUs:** Arm Mali drivers (seen on the Pixel 9a's Mali-G715) cached a render-pass entry per frame under Vulkan dynamic rendering and never freed it, so UI-heavy scenes grew ~100 MB/s until Android killed the game. Android now uses classic Vulkan render passes.
- **Precompiled C# on Android:** Release APKs compile the game's assemblies, `Index-ScriptCore` and the framework assemblies they use (including `System.Private.CoreLib`) ahead of time with Mono AOT and LLVM, instead of JIT-compiling them on the phone. Compute-heavy scripts run much faster: a 3D fluid simulation on a Pixel 9a went from about 30 to about 53 FPS (simulation step 1.5×, surface meshing 2.2× faster). Anything not precompiled still falls back to the JIT. The game assembly is loaded into the default load context on Android and iOS (there is no hot reload there). The first Release build spends about a minute compiling the framework once; later builds reuse the cache and add a few seconds. Build profile options `aot` (default: on for Release, off for Development) and `aotLlvm`.
- **Background audio:** `Audio.PlayInBackground = true` keeps sounds playing when the game is minimized, unfocused or sent to the background, and keeps scripts updating there (at a low rate, without rendering) so a music player can start the next track. On Android it runs a foreground media service with a "playing" notification; enable the Android build profile option `backgroundAudio` to declare it. Android games no longer freeze their main loop in the background; paused games poll about ten times a second until the OS suspends them.
- **Android runtime permissions:** `Application.RequestPermission` / `GetPermissionState` ask for permissions such as `READ_MEDIA_AUDIO`; the Android build profile's new `permissions` option declares them in the APK.
- **Scrolling lists of buttons on touch screens:** a drag that starts on a button (or any non-dragging widget) inside a Scroll Rect now scrolls the list once it moves a few units, and the button no longer clicks on release. Scroll Rects also scroll the right distance when the UI is scaled (a window smaller or larger than the reference resolution); before, the scroll range and drag speed were off by the UI scale.
- **Saving data:** `PlayerPrefs` (typed key/value settings) and `SaveData` (any object as JSON, per named slot). Both write atomically and save automatically on quit and when Play stops.
- **Gamepads from C#:** `Input.IsGamepadConnected`, `GetGamepadButton/Down/Up`, `GetGamepadAxis`, `GetLeftStick`, `GetRightStick`, `GetGamepadTrigger`, plus `GamepadButton` / `GamepadAxis`. `Input.GetAxis()` falls back to the first gamepad's stick or D-pad.
- **Collision layers:** every collider has **Layer** and **Collides With** checkbox fields (16 layers in the Inspector, 64 from code). Raycasts and overlap queries accept a `layerMask`; `PhysicsLayers.Mask(...)` builds one.
- **Collider settings from C#:** `IsSensor`, `Layer`, `CollisionMask`, `Friction` and `Bounciness` on `BoxCollider2D`, `CircleCollider2D` and `PolygonCollider2D` (shared `Collider2D` base class).
- **Sprite animation:** the **Sprite Animator 2D** component flips through sprite-sheet slices at a set frame rate (loop, play on start). Scripts control it with `SpriteAnimator2D.Play/Pause/Stop`, `Frame` and `FramesPerSecond`.
- **Post-processing from C#:** the `PostProcessing2D` component wrapper reads and changes every effect at runtime (`ColorGrading`, `Vignette`, `ChromaticAberration`, `Grain`, `Bloom`, `LensDistortion`, `Pixelated`, `GaussianBlur`), with the same value ranges as the Inspector. Works with `GetComponent`, `AddComponent` and component script fields.
- **Undo/redo for structural edits:** create, delete, duplicate, paste, cut, reparent, reorder, add/remove component or script, rename, enable/disable, Static and prefab unpack. The selection survives undo/redo.
- **Crash recovery:** unsaved scenes are copied to `.index/Recovery` every 30 seconds and on an unexpected error; the next start offers Restore or Discard.
- **Setup offers missing build tools:** `Setup.bat` / `Setup.sh` now also detect CMake, the MSVC toolset (Visual Studio 2022 Build Tools, default *no*) and the Linux C++ toolchain with X11/GL headers, and ask `[Y/n]` before installing them.
- **Custom project templates:** right-click a project in the Launcher → **Save as Template...** stores its `Assets/` structure, project settings, build profiles, native scripts and local packages as a template in `%LOCALAPPDATA%\Index\Templates`. **New Project** lists it with a **Custom** chip, and projects created from it start with the same folders, assets and Project Settings. The new **Templates** page in the Launcher sidebar shows custom and built-in templates with their preview image; it starts a new project from a template, saves a project as a template (**From Project**), and edits custom templates: name, description, category and source project (**Edit...**), **Open Source Project**, **Update from Source Project...** (re-copies the project's current state) and delete. Templates can also ship their own `project.json`, `BuildProfiles/`, `NativeScripts/Source/` and `Packages/`.
- **Launcher prerequisite check:** missing .NET 10 SDK or MSVC Build Tools are shown with a download button.
- **New app icons:** the Editor, Launcher and Runtime use the new flame icon (the Launcher on a framed tile), with simplified artwork at small sizes so it stays readable in the taskbar. Games without their own **App Icon** get the flame as their default icon and logo.
- Documentation: *Your First Game* walkthrough and *Known Limitations* page.
- **Android, iOS and Web exports as platform packages:** each target is a separate package (`Index.Platform.Android`, `Index.Platform.iOS`, `Index.Platform.Web`) instead of being built into the engine; a platform without its package is simply unavailable in Build Profiles. Android produces a signed APK, iOS an Xcode project or signed `.app` (macOS only), Web a static WebAssembly + WebGPU site. C# scripts run on these targets through the Mono runtime (`Index.ScriptRuntime.Mono`); C# on the Web needs the .NET 11 SDK with `wasm-tools`. See *Platform Packages* in the documentation.
- **Screen orientation for phones and tablets:** Project Settings > Display > Mobile > Orientation picks landscape (either side, left or right only), portrait (upright, upside down or both) or any combination; Android and iOS builds start in that orientation. Phone and tablet games always run fullscreen without the system bars.
- **UI respects notches and rounded corners on phones:** top-level UI anchors to the safe area, so corner buttons stay clear of the camera cutout. **Ignore Safe Area** on a RectTransform lets backgrounds and overlays reach the screen edges; scripts read the insets from `Application.SafeArea`.
- **UI Scale Mode:** Project Settings > Display > UI Scaling now offers **Fit** (the whole reference resolution stays visible on any aspect ratio, e.g. wide phones or tall windows) and **Fill** (covers the screen) besides **Match Width or Height**. Stored as `uiScaleMode` in `project.json`.
- **Fill Parent for UI rects:** **Fill Parent Width** / **Fill Parent Height** make a RectTransform span its parent rect (the screen's safe area for a root canvas) along that axis instead of using its Size, so a 1920×1080 canvas grows with wide phones, corner-anchored buttons stay in the screen corners, and a bottom toolbar can run the full width. Stored as `fillParent` (both axes), `fillWidth` or `fillHeight` in scenes and prefabs.
- **On-screen keyboard on Android and iOS:** focusing an Input Field opens the system keyboard (number pad for number fields, hidden text for secret fields) and keeps the field visible above it; closing the keyboard ends editing.
- **Build Profiles show platform requirements and options:** for package platforms the panel lists the package, the builder's requirement check with a fix for each missing tool, and editable platform options (signing keystore, orientation, SDK paths, ...). Options are stored as `platformOptions` in the `.build` file; `env:NAME` reads a value such as a password from an environment variable.
- **Files changed outside the editor apply live:** scenes, audio clips, fonts and Data Assets edited by another program (a text or audio editor, `git pull`, an AI agent) now reload while the project is open, like textures already did. A loaded scene with unsaved edits asks **Reload from Disk** / **Keep Editor Version** instead of being overwritten, and auto-save never overwrites an external change. **Preferences › Behavior › External Changes** decides whether unchanged scenes reload without asking.
- **3D foundation:** new built-in components **Transform 3D** (position, Euler rotation, scale; parented through the hierarchy), **Camera 3D** (perspective or orthographic), **Mesh Renderer** (Cube, Sphere, Plane, Cylinder with a color, lit or unlit) and **Directional Light** (color, intensity, ambient). A depth-tested 3D renderer draws them in the runtime and in the editor's Game View; 2D sprites and UI draw on top. C# gets `Transform3D`, `Camera3D`, `MeshRenderer` and `DirectionalLight`.
- **3D materials:** new `.material` asset (Asset Browser → **Create → Material**, edited in the Inspector) with base color, base color texture, metallic, roughness, emissive color/intensity, tiling/offset and a lit/unlit switch. Mesh Renderers reference it in the new **Material** slot; their Color now tints the material. Shading is physically based (GGX) in linear color space with tone mapping. C# gets a `Material` class (`AssetManager.Load<Material>`, `MeshRenderer.Material`).
- **Custom 3D meshes:** `.obj` files are mesh assets; a Mesh Renderer's new **Custom Mesh** slot draws one instead of the primitive (`customMesh` in scenes). Polygons are triangulated, missing normals are generated, edits on disk reload live, and picking/selection use the mesh bounds. **Mesh Collider 3D** collides with the renderer's custom mesh or its own **Custom Mesh**. C# gets a `Mesh` asset class (`AssetManager.Load<Mesh>`, `MeshRenderer.CustomMesh`, `MeshCollider3D.CustomMesh`).
- **3D collider gizmos:** in the 3D Editor View the selected entity's Box, Sphere, Capsule and Mesh Collider 3D are outlined (green, triggers light blue), visible through meshes.
- **Transparent materials:** a material's new **Surface** setting (`"surface": 1`) makes it alpha blended by Base Color alpha × texture alpha × the renderer's Color alpha. Transparent meshes are drawn after opaque ones, back to front per object, without writing depth. Lit transparent surfaces get more opaque at grazing angles (Fresnel), so glass and water mirror the sky when seen from the side. C#: `Material.Surface` / `MaterialSurface`.
- **Meshes built from C#:** `Mesh.Create()` makes an in-memory mesh that `SetData(positions, indices, normals, uvs)` fills or replaces at any time (normals are computed when left out); assign it to `MeshRenderer.CustomMesh`. Updating every frame is cheap: the GPU buffers are rewritten in place. `Clear()` empties it, `Destroy()` frees it, and meshes left over are freed when Play mode ends. Useful for procedural terrain, water surfaces, trails or marching-cubes output.
- **3D lights and shadows:** new **Point Light** and **Spot Light** components (range-limited inverse-square falloff, soft spot cone), any number of directional/point/spot lights per scene (up to *Max Lights* per frame), editor gizmos and **3D Entity** presets for both. The main Directional Light casts soft shadows from meshes with **Cast Shadows** on. C# gets `PointLight` and `SpotLight`.
- **3D particles:** new **Particle System 3D** component (and **3D Entity → Particle System 3D**) emits camera-facing billboards from a sphere, hemisphere, cone or box shape, with life time/speed/size variation, rotation, gravity, drag, bursts, Scale and Color over Lifetime, world or local simulation space, an optional texture (soft round dots without one) and **Alpha** or **Additive** blending. The 3D Editor View shows the emission shape and previews the effect with Play / Restart / Stop. C# gets `ParticleSystem3D` (`Play`, `Stop`, `Emit`, `Clear` and the main settings). See *3D → Particles* in the documentation.
- **3D sky:** Camera 3D has a **Background** setting; new cameras show a procedural gradient sky (top/horizon/ground colors, sun disc towards the main Directional Light) that also lights meshes as ambient (**Sky Ambient**). Cameras from existing scenes keep their solid clear color. Shown in the Editor View, Game View and runtime.
- **3D graphics settings:** Project Settings → Graphics → **3D Rendering** adds Shadow Quality, Shadow Distance, Max Lights, Exposure and Tone Mapping (saved under `graphics` in `project.json`, changeable at runtime through `RenderSettings` in C++ and C#).
- **3D physics (Jolt Physics):** new **Rigidbody 3D** (dynamic, kinematic or static; mass, drag, gravity scale, continuous collision, per-axis freeze, interpolation for smooth movement at high frame rates), **Box Collider 3D**, **Sphere Collider 3D**, **Capsule Collider 3D** and **Mesh Collider 3D** (the Mesh Renderer's mesh or a primitive, concave or convex). Colliders on child entities join their parent's Rigidbody 3D, colliders without one are static, and **Is Trigger** turns a body into a trigger. Physics runs in play mode and in the runtime. C# gets `Rigidbody3D` (velocities, `AddForce`/`AddTorque` with `ForceMode3D`, sleeping), the collider classes, `Physics3D.Raycast` and `Physics3D.Gravity`, and the `OnCollisionEnter3D/Stay3D/Exit3D` and `OnTriggerEnter3D/Stay3D/Exit3D` callbacks. See *Physics 3D* in the documentation.
- **3D Editor View:** a **3D** toggle in the Editor View toolbar switches to a perspective scene camera (right mouse orbits, with WASD/QE to fly; middle mouse pans; wheel zooms; **F** frames the selection), with a ground grid, click selection and a move/rotate/scale gizmo with undo. The Create menu gains a **3D Entity** submenu (Empty, Cube, Sphere, Plane, Cylinder, Camera 3D, Directional Light); in 3D mode **Create (Entity)** and **Camera** create 3D entities.
- **Project templates:** the Launcher's *Create New Project* dialog lets you pick **Empty 2D** or **Empty 3D**; new projects start empty (a camera, plus a directional light in 3D). Templates are folders under `templates/` (a `template.json` plus an `Assets/` tree), so new ones need no engine change.
- **Package versions and dependencies:** package `version`s are SemVer, `dependencies` can carry npm-style ranges (`"MyGame.Grid@^1.2.0"`), and a new `engine` field states which engine versions a release supports. Project generation, the runtime and the Package Manager all check them: dependencies load first and no longer need their own `project.json` entry, and a package whose dependency is missing, out of range or made for another engine is skipped with a clear error instead of crashing. The Package Manager installs missing dependencies along with a package, offers **Update** when the registry has a newer compatible release (with rollback if it fails), refuses to remove a package others still need, and reads multiple releases per registry entry.
- **packages-lock.json:** records the exact package versions and their sources next to `project.json`. Commit it; a fresh clone gets **Restore locked versions** in the Package Manager, which downloads the same releases and checks their SHA-256.
- **Engine modules:** 2D (sprites, 2D cameras/particles/post-processing, Box2D and Index-Physics) and 3D (meshes, materials, lights, 3D particles, Jolt) are optional modules a project lists in `project.json` `modules` (`"Index.2D"`, `"Index.3D"`). The Package Manager lists them under **Engine Modules** next to the packages (Install/Remove, then Reload Editor; CLI: `index package add|remove Index.3D`), and packages declare the modules they need with `modules = { "Index.2D" }` in `index-package.lua` (or `"modules"` in a registry release): installing such a package enables them, a module can't be removed while a package needs it, and a package whose module is off isn't loaded or built. The editor then offers only the enabled modules' components, presets and view mode, and disabled modules' systems, renderers and script APIs stay off. Game builds ship a runtime compiled without the unused modules (desktop through a premake runtime variant, Android/iOS/Web through the CMake `MODULES` option), and a build stops when a shipped scene uses a component of a disabled module. Projects without the field keep both modules; the built-in starter is 2D-only. An entity belongs to one world: 2D and 3D components (and either with a Rect Transform 2D) can't be combined — the Add Component menu, `Entity.AddComponent`, entity command buffers and Paste Component refuse the mix, and scenes that already contain one load with a warning and the foreign component inactive instead of crashing. See `Github-Docs/Documentation/Engine-Core/Engine-Modules.md`.
- **`index` command-line tool:** creates projects (`index create MyGame`), builds games without the editor (`index build --release --platform Windows`), runs them (`index run`), validates every project file the way the engine loads it (`index validate`), converts scenes/prefabs/Data Assets between JSON and binary (`index convert`), creates, applies, reverts and unpacks prefab instances (`index prefab`), slices sprite sheets (`index sprite slice`) and adds or removes packages (`index package`). `index.exe` ships next to the Launcher; `index setup-path` puts it on your user PATH. See *Command-Line Tool* in the documentation.
- **More external changes apply live:** `project.json` and build profiles edited outside the editor are reloaded instead of being overwritten on the next save, prefab instances in open scenes update when their `.prefab` changes on disk (overrides are kept), and Prefab Mode no longer auto-saves over a prefab that changed on disk (it reloads or asks). A `.meta` file that no longer parses is kept as `.meta.corrupt` and logged before it is replaced.

### Changed

- **Scene and prefab files list components in a fixed order:** Sprite Renderer, Camera 2D, Particle System 2D and the 3D components now follow the physics and audio components (Transform 2D stays first). Re-saving an existing scene reorders these keys once; values and loading are unchanged.

- **Index is now open source under the MIT License.** It can be used, modified and redistributed freely, including in commercial games; the previous custom license with a mandatory visible credit no longer applies.

- **`Application.PersistentDataPath` and `TemporaryCachePath` are per game:** `%LOCALAPPDATA%\<Company>\<Name>` instead of a folder shared by every Index game. Data written to the old `%LOCALAPPDATA%\Index` folder is not moved.
- **Faster C# hot reload:** saving a script now compiles it in-process with Roslyn from your .NET SDK instead of running `dotnet build` (one edited file in a 20-script project: about 20 ms of compile time instead of about 1.9 s). The compiler uses the exact settings `dotnet build` would use. Adding or deleting a `.cs` file costs one extra MSBuild pass (about 1 s), and project file or package changes still run one full `dotnet build`. Set `INDEX_SCRIPT_COMPILER=dotnet` to always use `dotnet build`.
- **Debug overlays on phones:** Android and iOS builds show the runtime stats and log overlays from the start whenever they are enabled, since there are no F6/F7 keys to open them.
- **Play no longer saves scenes.** Unsaved edits are snapshotted privately and are still unsaved after Stop.
- The collider **Layer Mask** number field is now a **Layer** checkbox dropdown.
- **New projects store scenes and prefabs as JSON** (readable diffs, editable by tools and agents); builds still ship them as binary. Existing projects keep their setting; `index convert --format json` switches one.
- **Converting the asset format now includes Data Assets:** changing Project Settings › Editor › Asset format (and `index convert`) also rewrites `.dataasset` files, which previously kept their old encoding.
- **Builds only ship assets the game uses:** unreferenced files from `Assets/` and `IndexAssets/` (unused fonts, textures, shaders, `.cs` sources, scenes not in the build list) are left out. References are followed from the build scenes through GUIDs, asset paths and scene names, plus path literals and `AssetManager.FindAll` calls in C# scripts. Files only found through computed paths belong in `Assets/StreamingAssets/`, which always ships. See *Building and Shipping › Which assets ship*.
- The Build panel's output directory follows the active profile's platform (`Builds/Android`, `Builds/Web`, ...) as long as its last folder is a platform name; custom folder names are kept.
- **Faster frames in script- and sprite-heavy scenes:** component access from C# no longer scans every component type on each call; spawning or destroying non-Static sprites no longer rebuilds the Static sprite grid; unsliced sprites skip the sprite-sheet lookup; prefabs are read from disk once instead of on every instance or spawn; bloom renders at half resolution with at most 25 blur taps (same glow radius); and the profiler costs almost nothing while its panel is closed.
- New `Entity.TransformRefReadOnly` and `GetNativeComponentReadOnly<T>()`: read a transform without making the engine re-check every transform that frame, as the writable `TransformRef` does. `Index-ScriptCore.dll` and the engine must be updated together (script interop layout version 5).
- `Window.IsFullScreen`, `Window.Position`, `Window.Title` and `Window.Minimize/Maximize/Restore()` are ignored inside the editor, where they used to resize or move the editor itself; they still apply in the built game.
- **Window, input and gamepads now run on SDL3 instead of GLFW.** Games ship `SDL3.dll` instead of `GLFW.dll` (the Build panel copies it automatically). `KeyCode`, `MouseButton`, `GamepadButton` and `GamepadAxis` keep their values, so scripts and saved bindings are unaffected. Gamepads are hot-plugged and recognized through SDL's controller database, and high-DPI displays (Retina, Windows scaling) report correct sizes.
- `Packages/IndexPackages.props` is the same file on every OS: it picks the package output and `Bin/<platform>-<arch>` folders through MSBuild conditions, so a project committed on Windows builds unchanged on Linux and macOS. Managed packages prebuilt only for Windows are used on the other platforms too.
- `index setup-path` works on Linux and macOS: it installs an `index` launcher script in `~/.local/bin`.
- **Platform services are portable:** file and folder dialogs, message boxes, opening files/URLs, "Show in Explorer", system theme and language detection, user folders and dynamic library loading go through one platform layer built on SDL3. The engine code now compiles for Windows, macOS, Linux, Android, iOS and Web; see *Known Limitations* for which targets can already be exported.

### Fixed

- Blurry taskbar icon on Windows with display scaling above 100 %: the Editor, Launcher and games without their own **App Icon** showed the 32 px icon scaled up. The window now gets the embedded icon at the exact size for the monitor's DPI.
- Native project packages stopped loading after the engine was rebuilt ("package was built against a different Index-Engine binary"), and tilemaps and other package components vanished until someone rebuilt the package by hand. Opening a project in the editor now rebuilds every source package under `Packages/` that has no build for the running engine (never built, or built against another `Index-Engine.dll`) before packages load. The editor window appears once the build is done; a failed build is logged and the package stays unloaded.
- Smoother motion with VSync: the frame delta time is now snapped to the display's refresh interval instead of the jittery measured gap between frames (±25 % at 144 Hz), which made everything that moves judder. Game time still follows real time.
- 3D physics: balls and other dynamic bodies no longer hop when they roll across the edge between two triangles of a mesh collider (Jolt's enhanced internal edge removal is on for dynamic bodies).
- Game builds ship the engine's current built-in assets (`IndexAssets`): the copy a project receives when it is created now only overrides files that were changed in the project. Before, a build shipped that snapshot unchanged, so older projects kept outdated built-ins such as the previous engine icon on the splash screen.
- Restarting the current scene from a script (`SceneManager.LoadScene` on the active scene, e.g. a "Restart" button) no longer floods the log with "… is no longer attached to a live entity": unloading the old copy invalidated the C# component references the freshly loaded copy had just picked up.
- C#: `RectTransform.Entity` returned nothing for UI entities, because it required a `Transform2D` that UI entities never have.

- **The `index` CLI no longer deletes components when it rewrites a scene or prefab** (`prefab create/apply/revert/unpack`): 3D components (Transform 3D, Camera 3D, Mesh Renderer, lights, 3D physics), UI widgets and layout groups, Sprite Animator 2D, Post Processing 2D and other registry-serialized components were silently dropped because they were only saved while the editor or a game was running.
- The Launcher's **Open** and **Run** buttons work on the first click: on a project that wasn't selected yet, the buttons disappeared while the mouse button was held, so the click only selected the project.
- The Launcher's project preview now shows 3D scenes: it renders through the scene's Camera 3D like the Game View (before, 3D projects got only the 2D layer or no preview at all).
- The Editor View's **3D** toggle is remembered per project (`editorView3D` in `project.json`) instead of resetting to the project's default on every start.
- **Stopping Play froze the editor for seconds** in scenes with many prefab instances or scripted entities (about 2 s at 3,000 entities): reloading the edit scene wrote a log line for every prefab override and every script field. Loading scenes, in the editor and in built games, is faster for the same reason.
- Android: games no longer stay black on GPUs that reject the opaque surface mode (e.g. Mali), recover their picture after returning from the background or after the screen was locked (unlocking left the screen black), and stop their music as soon as they go to the background (it kept playing on the home screen until the app was reopened). Saves go to the app's own storage, and `OnApplicationPaused` also saves `PlayerPrefs`, since the system may end a backgrounded app without a quit.
- `Input.GetKeyDown`/`GetKeyUp` and `GetMouseDown`/`GetMouseUp` no longer miss a press and release that arrive within one frame. Backspace on Android's on-screen keyboard now deletes text, and very short taps now press buttons.
- `UIPointer.HoveredEntity` reports what is under the pointer now instead of what was under it last frame. On touch screens the finger jumps to where it lands, so a tap on a button looked like a tap on the game world (e.g. it deselected objects in a level editor).
- Input Field caret and selection are drawn at the field's sorting order (they were hidden behind panels with a higher order, e.g. a field in a popup), and the caret is at least one logical pixel wide so it is visible on high-density phone screens.
- **App icon:** icons larger than 256×256 (the usual 512/1024 px PNGs) were not embedded in Windows builds, so the game kept the Index icon. The `.exe` now carries every size from 16 to 256 px, built from any PNG, JPG, BMP or ICO. Icons outside `Assets/` or in `.ico` format now also reach the running game. Platform packages always get a PNG (previously only files ending exactly in `.png`) and the app id `com.<company>.<name>`. On Linux every Index game used to share the app id `dev.index.engine`.
- **Custom cursors:** cursors stay the right size at 125–400 % display scaling (they used to shrink on Windows), keep their aspect ratio instead of being stretched to a square, and have a configurable **Hotspot** (Project Settings › Branding › Cursors, or `Cursor.SetTexture(texture, hotspot)` in C#); previously the click point was always the top-left pixel. On Android and iOS cursor settings are ignored without a warning.
- The editor crashed while closing when the project used the Vulkan render backend.
- **Sliders** take presses on both the handle and the track: grabbing the handle drags it from where it was grabbed, and clicking the bare track jumps the value to the pointer. Previously a handle with its own Interactable disabled the track, and without one only the track rect reacted, so most of a large handle was dead.
- `Cursor.Visible = false` now hides the cursor over the Game View during Play in the editor; the editor UI used to show it again every frame unless the project had a custom cursor image.
- An exception during a frame used to close the editor without warning; it now keeps unsaved scenes for recovery and explains what happened.
- A last-opened scene that cannot be read no longer leaves the editor with no scene; an empty unsaved scene opens and the file is left untouched.
- Exceptions in UI event handlers, coroutines and several other script entry points no longer terminate the process; they are logged to the Console.
- Errors from `OnApplicationQuit`, `OnApplicationPaused` and `OnFocusChanged` handlers now appear in the Console instead of being lost.
- Crash dumps are also written for `std::terminate`, `abort()`, pure virtual calls and invalid CRT parameters.
- A game started without the .NET 10 Runtime shows a message with a download link.
- `Gizmo.DrawLine(start, direction, distance)` no longer throws `NotImplementedException`.
- Prefab instances spawned after a scene change no longer render solid white: the fast-spawn prefab cache kept texture handles that the scene unload had already freed.
- Textures that were being written while the editor read them (or whose `.meta` was mid-write) no longer stay white: the editor retries them on the next file change and also watches `.meta` files.
- **VSync off is no longer capped at the monitor refresh rate on Direct3D 12.** Presents now allow tearing, so `Application.VsyncEnabled = false` runs up to `Application.TargetFrameRate` in windowed and fullscreen mode. The frame cap is also more accurate (240 instead of ~233). The chosen present mode is logged.
- Release reliability, packaging, and data-safety fixes.
