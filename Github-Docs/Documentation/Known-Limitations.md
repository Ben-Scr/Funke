# Known Limitations (Beta)

Funke is in beta. This page records platform restrictions, core-only boundaries and remaining feature limits. **Optional external packages are part of Funke's available functionality:** a feature absent from the core is not necessarily missing from Funke. See the [package overview](README.md#packages) and each package's documentation before treating a core restriction as an engine-wide limitation. Please report unexpected behavior as a bug.

Reference games are also distributed separately through the Launcher's **Asset Library**, including **NeonStack** and **Voxtau**. The [Asset Library catalog](https://github.com/Ben-Scr/Funke-AssetLibrary) contains these projects; the built-in [project templates](Editor/Editor.md#project-templates) provide either a blank scene or a playable 2D or 3D physics example.

## Platforms

- **Desktop games are exported for the editor's own platform.** The Windows editor builds Windows games, the Linux editor Linux games and the macOS editor macOS games (an `.app` bundle); there is no cross-export between desktop platforms yet.
- **Linux and macOS are new.** They have had far less testing than Windows. macOS games are ad-hoc signed but not notarized, so Gatekeeper asks before the first launch on other Macs (right-click › **Open**). Dragging assets from the Asset Browser to other applications works on Windows only.
- **Android, iOS and Web exports are new.** They come from platform packages ([Platform Packages](Editor/Platform-Packages.md)) and need extra SDKs. Android builds arm64-v8a only and has had little on-device testing; the iOS package needs a Mac and has not been verified on a device yet; Web needs a browser with WebGPU.
- **Bolt export support depends on the target.** Windows x64 Release exports use AOT. Editor Play mode and Development players use Fast-JIT. The installed Bolt emitter fails during cross-target code generation for EntityMover with the Funke library. See [platform package exports](Scripting/Bolt.md#platform-package-exports). See [Bolt desktop exports](Scripting/Bolt.md#desktop-exports).
- **C# on Android, iOS and Web runs on Mono.** iOS and Web use the interpreter, which is noticeably slower than the desktop JIT, and culture-sensitive formatting uses invariant rules everywhere outside the desktop.
- Desktop builds include a private **.NET 10 Runtime** by default; disabling **Include .NET Runtime** requires players to install it separately. Windows players still need the **Visual C++ Redistributable**. Mobile and Web builds bundle their Mono runtime.
- **Web builds have additional limits.** C# games need the .NET 11 SDK with `wasm-tools`; scripts run interpreted, the class library is not trimmed, and jobs run sequentially in the current browser build. See [Platform Packages](Editor/Platform-Packages.md#web).

## Feature availability and remaining limits

| Feature | Current support and remaining limit |
|---|---|
| Animation blend trees, layers, avatar masks, root motion | The Animator plays one state machine layer with crossfades; drive extra motion from a script. |
| Tilemaps | Available through the optional external [Funke.Tilemap2D](https://github.com/Ben-Scr/Funke-PackageRegistry/tree/main/packages/Funke.Tilemap2D) package, with chunked tile storage, rendering, Inspector support and C++/C# APIs. Install through the Package Manager; consult the package README for its capabilities and limits. Sprite entities and prefabs remain an alternative for projects without the package. |
| 2D lighting | Available through the optional external `Funke.Lighting2D` package: ambient light, up to 32 point lights and 64 rectangular shadow occluders. This version has hard shadows, one lighting plane and no normal maps or per-layer light masks. Mobile/Web performance and device compatibility still need validation. See [Lighting 2D](Engine-Core/Lighting-2D.md). |
| Physics joint types | [2D physics](Engine-Core/Physics-2D.md#joints) provides revolute, prismatic and weld joints. Other joint types are not exposed by the built-in 2D components. |
| Model import | `.obj`, `.gltf` and `.glb` meshes and glTF skeletal animation are supported. OBJ imports named MTL slots and plain diffuse maps. glTF imports material slots, textures and alpha modes. Both support slot overrides. FBX and morph targets are unsupported. Only TEXCOORD_0 is supported; requested other UV sets and KHR_texture_transform fail explicitly. A Windows D3D12 fixture passed all four pixel comparisons across Edit, Play, stripped export and live reimport. See the [workflow and tested configurations](Engine-Core/3D-Asset-Workflow-Verification.md). |
| Standard 3D materials and lighting | Base-color, normal, packed metallic/roughness, emissive and occlusion maps, alpha cutout and double-sided surfaces are implemented. The [Windows D3D12 acceptance run](Editor/Acceptance-2026-11-20.md#material-and-import-workflow) exercised three animated primitives, an external image and a material override. Pixel parity on other graphics backends requires its own run. Only the main directional light casts shadows; point/spot shadows are not available. MSAA 4x is available for 3D geometry. |
| Split screen and camera follow | Multiple camera entities can exist, but each scene selects one main 2D camera and the game uses the first enabled 3D camera. A scheduled 3D Inspector follow/orbit rig and explicit C# 2D/3D helpers are available in source; see [Camera follow](Engine-Core/Camera-Follow.md). Split screen, camera collision and a 2D Inspector rig are not provided. |
| Core audio mixing | Spatial Audio Sources, optional headphone HRTF and `Audio.PlayOneShotAt` are available; `AudioStream` streams files from disk. The core exposes per-source and master volume, without mixer groups. See [Spatial audio](Engine-Core/Spatial-Audio.md) and the [scripting examples](Scripting/Scripting.md#what-scripts-can-do-the-api) for the optional mixer package. |
| Input action maps and rebinding | Available through the optional external [Funke.Input](https://github.com/Ben-Scr/Funke-PackageRegistry/tree/main/packages/Funke.Input) package, including keyboard/mouse/gamepad bindings and saved rebinding. Consult the package README for version-specific authoring tools and engine requirements. The core also supports direct polling (`Input.GetKey`, `Input.GetGamepadButton`). |
| Asynchronous scene activation and asset streaming | `LoadSceneAsync` prepares files/assets on workers and constructs an unpublished scene in cooperative batches, including individual prefab entities and parent links. Texture transfers are chunked; allocation, one transfer, mip generation, prefab preparation/fixups, callbacks, finalization and teardown can still exceed the budget. File preparation requires threads; threadless Web builds report failure. See [cooperative loading and verification](Engine-Core/Cooperative-Loading.md). |
| Asset packaging | Optional `.fbundle` archives and lossless LZ4 or Zstandard compression are supported. Bundles are not encryption; direct filesystem consumers need loose files under `Assets/StreamingAssets/`. See [Asset bundles](Editor/Building-and-Shipping.md#asset-bundles). |
| Localization authoring | Games have string tables, a C# API, Localized Text, transient [language preview](Engine-Core/Localization.md#editor-language-preview) and optional LocalizedUI bindings. The new [String Tables editor](Editor/String-Tables.md) edits the existing format with conflict checks and history. The rebuilt Windows editor passed the visible authoring and preview checks. Unbound/procedural text stays literal. |
| Text shaping and font coverage | Ordered project [font fallback families](Assets/Font-Fallbacks.md) select missing glyphs from additional fonts and share metrics with layout/caret code. Null-backend layout/atlas tests pass; visible real-GPU acceptance is pending. Missing glyphs still use replacement characters when no configured font provides them. Bidirectional layout, OpenType shaping, combining-mark positioning and color emoji remain unsupported. First-use font/glyph work can stall. |
| Prefab variant authoring | Create Variant, inherited/local component badges and reset are implemented in source; the matching Editor UI acceptance is still pending. Inherited child additions/deletions/reparenting are rejected on save; stale-base editing requires reopening. See [Prefab variants](Editor/Prefab-Variants.md). |

## Editor

The [Windows workflow acceptance](Editor/Acceptance-2026-11-20.md) records the Play/Stop/recompile memory run and the saved-scene, prefab and failed-compilation checks. See [editor state ownership](Editor/Editor-State-Ownership.md) for which histories survive each transition.

- Undo and redo history belong to each loaded scene instance and are not saved with the scene. Switching between loaded scenes, entering and leaving Prefab Mode, and a successful Play/Stop round trip preserve edit-scene histories. Closing, replacing or reloading a scene discards its history; closing Prefab Mode discards the prefab's own history. Reload/close controls and existing save/conflict dialogs explain this. When a scene or prefab history is discarded, the status bar identifies the affected scene or file; click or hover the status for details. Reopening starts a new history. Failed play-mode restoration discards the suspended histories and reports the loss.
- Moving entities between two loaded scenes creates a linked undo step. It can be applied only while both histories retain that step at the top. Disabled Undo/Redo items explain the partner scene, how many preceding steps must be applied there, and the first step's label; the command palette also shows the explanation for keyboard selection. A shortcut attempt reports the block in the status bar. No partner edits are undone automatically. Closing the partner or discarding its history can make the linked step permanently unavailable; reopening the scene does not reconnect it. A blocked attempt retains the local step and does not move either history. Each history retains at most 256 steps; new edits discard its redo branch.
- The Asset Browser has a separate project-session history for its recorded file operations; external edits are not recorded. Undo/redo refuses to replace a later file, modified contents or metadata, changed directory children, or an unexpected file type. A blocked attempt shows the affected path and conflict in the status bar (click or hover for details) and keeps the step for a safe retry after the conflict is resolved. Existing rollback and GUID checks still apply. Back up external contents before manually resolving a conflict; history does not contain their previous versions. If rollback cannot complete, the error identifies the retained recovery directory for inspection. These histories end when the project session ends.
- Texture previews decode on a worker and upload across frames. Texture allocation and GPU upload still require the main thread; asynchronous previews do not guarantee a fixed frame time for arbitrarily large images.
- Hot reload keeps the previous working assembly when a replacement cannot be read or its types cannot be resolved. A first load without any working assembly still needs a successful build; script lifecycle callbacks can run again when instances restart after a reload attempt.

## Packages

- Native dependencies are resolved transitively and loaded before their dependents. Missing or incompatible dependencies prevent the affected packages from loading; inspect the package log for the reason.
- `packages-lock.json` records exact package versions. **Restore locked versions** restores registry releases with their recorded URL and SHA-256; Git and local packages still need to be reinstalled or copied manually. See [Packages](Packages/Package-System.md#packages-lockjson).
