# 3D

Funke started as a 2D engine. This page covers the 3D foundation: what exists, how it fits next to 2D, and what is still missing.

## Components

| Component | Fields | Notes |
|---|---|---|
| **Transform 3D** (`Transform3D`) | Position, Rotation (Euler degrees: X pitch, Y yaw, Z roll), Scale | Local to the parent's Transform 3D. Conflicts with Transform 2D and Rect Transform 2D. |
| **Camera 3D** (`Camera3D`) | Projection (Perspective / Orthographic), Field Of View (vertical, degrees), Orthographic Size, Near Clip, Far Clip, Background (Skybox / Solid Color), Clear Color, Skybox Material, Sky Top / Sky Horizon / Sky Ground, Sun Size, Sky Ambient, Ambient From Skybox, Fog, Fog Color, Fog Start, Fog End | Looks down its local −Z axis. The first enabled Camera 3D of the loaded scenes renders the game. See [Sky](#sky) and [Fog](#fog). |
| **Mesh Renderer** (`MeshRenderer`) | Mesh (Cube, Sphere, Plane, Cylinder), Material, Color, Lit, Cast Shadows | Built-in primitives, 1 unit in size. Plane lies flat (XZ) and faces +Y. Color tints the material. Lit only applies without a material. |
| **Skinned Mesh Renderer** (`SkinnedMeshRenderer`) | Model, Material, Color, Lit, Cast Shadows, Clip, Speed, Loop, Play On Awake, Preview In Edit Mode, Culling Mode, Distance Rate, Half / Quarter Rate From | Draws an animated glTF model and plays one of its clips. See [Skeletal animation](#skeletal-animation). Can't share an entity with a Mesh Renderer. |
| **Directional Light** (`DirectionalLight`) | Color, Intensity, Ambient, Cast Shadows | Shines along its local −Z axis. The first enabled one is the *main* light: its Ambient is the flat ambient, it draws the sun disc and it is the only light that casts shadows. |
| **Point Light** (`PointLight`) | Color, Intensity (default 4), Range (default 10) | Shines in all directions from its position and fades to zero at Range. |
| **Spot Light** (`SpotLight`) | Color, Intensity (default 6), Range (default 15), Inner Angle (default 20°), Outer Angle (default 30°) | Cone along its local −Z axis; full intensity inside Inner Angle, fading to zero at Outer Angle (both half angles). |

Every 3D component needs a Transform 3D; the editor adds it when you add them from **Add Component**. An entity holds at most one light component. A scene without any light component gets a default light from above, so meshes are never black.

World matrices come from `Transform3DHierarchySystem`, which runs before the scripts every frame. A child of an entity without a Transform 3D (for example an empty grouping entity) still inherits the transform of the nearest ancestor that has one.

Scene JSON keys: `Transform3D` (`posX/posY/posZ`, `rotX/rotY/rotZ`, `scaleX/scaleY/scaleZ`), `Camera3D` (`projection`, `fov`, `orthoSize`, `near`, `far`, `background`, `clearColor`, `skyTop`, `skyHorizon`, `skyGround`, `sunSize`, `skyAmbient`, `fog`, `fogColor`, `fogStart`, `fogEnd`), `MeshRenderer` (`mesh` 0–3, `customMesh`, `material`, `color`, `lit`, `castShadows`), `SkinnedMeshRenderer` (`model`, `material`, `color`, `lit`, `castShadows`, `clip`, `speed`, `loop`, `playOnAwake`, `previewInEditMode`, and only when changed `cullingMode`, `distanceRate`, `halfRateDistance`, `quarterRateDistance`), `DirectionalLight` (`color`, `intensity`, `ambient`, `castShadows`), `PointLight` (`color`, `intensity`, `range`), `SpotLight` (`color`, `intensity`, `range`, `innerAngle`, `outerAngle`). Missing keys take the defaults, so scenes saved before these fields existed still load.

## Materials

A material is a `.material` asset: a small JSON file with a GUID in its `.meta`, like every other asset. Its **Shader** field can pick your own `.wgsl` shader instead of the standard PBR shader described here; see [Custom Shaders](Custom-Shaders.md). Create one with **Create → Material** in the Asset Browser, select it to edit it in the Inspector (every change is saved to the file right away), and drag it onto a Mesh Renderer's **Material** slot or pick it there.

| Field | Default | Meaning |
|---|---|---|
| Lit | on | Off ignores lights, exposure and tone mapping and shows Base Color (plus emissive) exactly. |
| Surface | Opaque | **Transparent** blends the surface over what is behind it (see [Transparency](#transparency)). |
| Base Color | white | sRGB color; its alpha is the opacity of a Transparent material. |
| Base Color Texture | none | Texture asset multiplied into Base Color; sampled with repeat wrapping (point filtering if the texture's import filter is Point, linear otherwise). |
| Metallic | 0 | 0 = plastic/wood/stone, 1 = metal. |
| Roughness | 0.5 | 0 = mirror-like highlight, 1 = fully matte. |
| Emissive Color / Intensity | black / 1 | Light the surface gives off itself (not lighting other objects). |
| Tiling / Offset | (1,1) / (0,0) | UV scale and shift of the texture. |

On disk (`Assets/Materials/Gold.material`):

```json
{
  "type": "Material", "version": 1, "lit": true, "surface": 0,
  "baseColor": { "r": 1.0, "g": 0.78, "b": 0.34, "a": 1.0 },
  "baseColorTexture": "0",
  "metallic": 1.0, "roughness": 0.3,
  "emissiveColor": { "r": 0, "g": 0, "b": 0, "a": 1 }, "emissiveIntensity": 1.0,
  "tiling": { "x": 1, "y": 1 }, "offset": { "x": 0, "y": 0 }
}
```

GUIDs (`baseColorTexture` here, `material` in the scene) are written as decimal strings. All Mesh Renderers that use a material share it: editing the file (in the editor or outside it) updates all of them. A Mesh Renderer without a material uses a white default material (metallic 0, roughness 0.5) tinted by its Color, and its own Lit flag. Build asset pruning keeps every material a shipped scene references and every texture such a material references.

### Transparency

A material with **Surface = Transparent** (`"surface": 1`) is alpha blended. Its opacity is Base Color alpha × texture alpha × the Mesh Renderer's Color alpha, so one glass material can be made more or less see-through per renderer. Transparent meshes are drawn after all opaque ones, sorted per object from the farthest to the nearest (by the centre of the mesh bounds), with depth testing but without writing depth. Lighting, emissive and unlit materials work as for opaque surfaces. Lit transparent surfaces follow Fresnel: reflected light is not filtered by the transparency, so the surface turns more opaque and mirror-like at grazing angles — a low roughness (≈ 0.03) gives water and glass a clear sky reflection.

Limits: sorting is per object, so two transparent meshes that intersect, or one large concave transparent mesh, can show parts in the wrong order. Only front faces are drawn. A transparent mesh with **Cast Shadows** on casts a full (opaque) shadow; turn it off for glass.

## Custom meshes

Besides the built-in primitives a Mesh Renderer can draw a mesh asset: drop a Wavefront `.obj` or a glTF 2.0 file (`.gltf`, `.glb`) into `Assets/` and pick it in the renderer's **Custom Mesh** slot (`"customMesh": "<guid>"` in the scene). While a custom mesh is set the primitive **Mesh** field is ignored; clearing the slot draws the primitive again.

- glTF: every triangle mesh of the file's scene is merged into one mesh, placed by its node transforms. A Mesh Renderer draws an animated model in its rest pose; use a [Skinned Mesh Renderer](#skeletal-animation) to play it. Buffers can be embedded (`.glb`, base64 `data:` URIs) or separate files next to the `.gltf`. Materials, textures, cameras, lights and morph targets in the file are ignored — assign a `.material` as usual.
- Read from an OBJ file: positions, texture coordinates and normals (`v`, `vt`, `vn`, `f`); faces with more than three corners are triangulated, negative (relative) indices work, and all objects and groups in the file become one mesh. Materials (`mtllib`, `usemtl`), lines and points are ignored — assign a `.material` as usual.
- Missing normals are computed as smooth normals per position; missing texture coordinates are 0.
- Faces should wind counter-clockwise seen from outside (the OBJ convention); back faces are culled. The mesh keeps the file's units and origin — scale it with the Transform 3D.
- A file that cannot be read draws nothing and logs a warning; fixing the file reloads it, and edits made outside the editor reload live. Picking, the selection box and **F** (frame) use the mesh's bounds.
- **Mesh Collider 3D** collides with the custom mesh of the entity's Mesh Renderer (**Use Mesh Renderer**), or with its own **Custom Mesh**.

### Meshes built from code

`Mesh.Create()` returns an empty in-memory mesh for geometry a script computes: procedural terrain, a water surface from a fluid simulation, trails. Fill it with `SetData` and assign it like a mesh asset:

```csharp
Mesh surface = Mesh.Create();
GetComponent<MeshRenderer>()!.CustomMesh = surface;

// Any time, as often as every frame: replaces the whole geometry.
surface.SetData(positions, indices);              // ReadOnlySpan<Vector3>, ReadOnlySpan<int> (triangle list)
surface.SetData(positions, indices, normals, uvs); // optional per-vertex normals and UVs
```

- Positions are in the entity's local space; indices are a triangle list wound counter-clockwise seen from outside (back faces are culled). Without normals, smooth normals are computed from the triangles; without UVs they are 0.
- `SetData` throws `ArgumentException` when normals/UVs don't match the vertex count or an index is out of range, and `InvalidOperationException` on a mesh asset or a destroyed mesh. `Clear()` removes all geometry (the renderer draws nothing), `Destroy()` frees the mesh; runtime meshes still alive when Play mode ends are freed then. `IsRuntime` tells them apart from `.obj` assets.
- Rewriting a mesh every frame is cheap: its GPU buffers only grow and are rewritten in place. Lists of vertices can be passed without copying via `CollectionsMarshal.AsSpan(list)`.
- Runtime meshes are not saved: a scene stores the renderer's primitive **Mesh**, so author a placeholder primitive (e.g. a Plane where the water will be) for the Editor View and assign the runtime mesh in `OnStart`.
- A Mesh Collider 3D can use a runtime mesh too; it rebuilds its shape whenever the geometry changes, which is expensive for large meshes updated every frame.

Build asset pruning keeps every `.obj` a shipped scene references.

## Skeletal animation

A **Skinned Mesh Renderer** draws an animated glTF model (`.glb` or `.gltf`, exported for example from Blender with *Skinning* and *Animation* enabled) and plays its clips:

1. Drop the model into `Assets/` and pick it in **Model**. The inspector lists the model's clips under **Pick Clip** with their length, plus its vertex, node, joint and clip counts.
2. Leave **Clip** empty to play the first clip, or pick or type a clip name. **Speed** scales playback (negative plays backwards), **Loop** repeats the clip, otherwise it holds its last frame.
3. **Play On Awake** starts the clip when Play begins. In edit mode the renderer shows the clip's first frame; **Preview In Edit Mode** plays it in the editor too.

How it works:

- Skins (up to four joint weights per vertex) and node animation both animate: rigid parts parented to an animated node (a robot arm, a door) move with that node. Translation, rotation and scale channels are read with Linear, Step and Cubic Spline interpolation.
- Skinning runs on the CPU and the posed mesh goes through the regular mesh pass, so materials, custom shaders, transparency, fog and shadows behave exactly as on a Mesh Renderer. A model is re-posed only when its pose changes. This is meant for player characters, enemies and props in the dozens, not crowds of thousands.
- **Culling Mode** and **Distance Rate** work as on the Animator (see [Animation > Culling and distance rate](Animation.md#culling-and-distance-rate)): off screen (Cull Pose) or far from the camera, the model keeps its last skinned pose and is re-skinned only on its update frames, every 2nd or 4th frame. The play head itself keeps the exact time, so `Time`, `IsPlaying` and the end of a one-shot clip stay right for scripts. Off screen means outside the camera's view with the model's rest-pose bounds plus a margin.
- Picking, the selection box and **F** use the bounds of the pose the model is drawn in (the clip's first frame in edit mode, the current frame while it plays).

From a script:

```csharp
public class PlayerAnimation : EntityScript
{
    private SkinnedMeshRenderer? m_Model;

    public override void OnStart() => m_Model = GetComponent<SkinnedMeshRenderer>();

    public override void OnUpdate()
    {
        bool moving = Input.GetAxis().Length() > 0.1f;
        m_Model!.Play(moving ? "Run" : "Idle", crossFade: 0.2f);
    }
}
```

`Play(clip, crossFade = 0.2f)` blends from the current pose to the new clip over `crossFade` seconds; calling it again for the clip that is already playing does nothing, so it is safe to call every frame. `Pause()`, `Resume()` and `Stop()` (back to the first frame) control playback; `Clip`, `IsPlaying`, `Time`, `Speed`, `Loop`, `PlayOnAwake`, `ClipNames` and `GetClipLength(name)` read or change it. `TryGetBone("Hand.R", out position, out forward, out up)` returns a bone's (or any model node's) world position and axes in the drawn pose, e.g. to place a sword in a hand every frame; while culling or the distance rate holds the pose back, the bone stays with the drawn model. `Model`, `Material`, `Color`, `Lit` and `CastShadows` work like on a Mesh Renderer; `CullingMode`, `DistanceRate`, `HalfRateDistance` and `QuarterRateDistance` like on the Animator.

## Lights and shading

Lighting is physically based (GGX/Cook-Torrance specular with Lambert diffuse) and runs in linear color space: colors you pick are sRGB and converted before lighting. A white light with intensity 1 lights a white surface facing it to full brightness.

- **Directional lights** have no falloff. **Point and spot lights** fall off with the inverse square of the distance, smoothly windowed so they reach exactly zero at Range. Intensity is therefore "brightness at about one unit away"; raise it or the range for larger rooms.
- **Ambient:** the main directional light's Ambient color is added everywhere. With a sky background, the sky colors add hemispheric ambient (top color from above, ground color from below), scaled by the camera's **Sky Ambient**; metals reflect the sky with it. With a Skybox Material, **Ambient From Skybox** takes these colors from the material instead: a Gradient Sky's top/horizon/ground colors, the averaged upper, middle and lower band of a Panoramic Sky's image (× tint × exposure), or a 6-Sided Sky's up, side and down faces (× their colors × exposure). Texture averages are computed once per texture (`ambientFromSkybox` in scenes).
- **Light limit:** each frame uses at most **Max Lights** lights (Project Settings → Graphics → 3D Rendering, default 16, at most 64). Directional lights come first, then the point and spot lights whose range is closest to the camera.
- **Shadows:** the main directional light casts shadows from every Mesh Renderer with **Cast Shadows** on, onto everything within **Shadow Distance** of the camera (default 40 units). The shadow map is soft-edged (3×3 PCF) and fades out at the distance limit. **Shadow Quality** picks the map size (Off, Low 1024, Medium 2048, High 4096). Point and spot lights do not cast shadows.
- **Exposure** and **Tone Mapping** (None, Reinhard, ACES — default ACES) map the lit result to the screen. They do not affect unlit materials or the sky.

## Sky

New Camera 3Ds use **Background = Skybox**: a procedural gradient (Sky Top above, Sky Horizon at the horizon, Sky Ground below) drawn behind all meshes, with a sun disc in the direction of the main directional light, tinted by its color. **Sun Size** is the disc's angular radius in degrees (0 hides it). No texture is needed. **Solid Color** clears to Clear Color instead and also turns off the sky ambient.

**Skybox Material:** assign a `.material` whose shader targets `Skybox` and the camera draws it instead of the gradient (the gradient colors still drive the sky ambient). **Create → Skybox Shader** in the Project panel writes one of three ready-made shaders into the folder:

| Shader | What it shows |
|---|---|
| **Gradient Sky** | The gradient above as a material (top / horizon / ground, curve, sun on or off) |
| **6-Sided Sky** | A cube: per face (front = −Z, back, left, right, up, down) a texture times a color, so a face can be a plain color; rotation and exposure |
| **Panoramic Sky** | An equirectangular (2:1) image around the camera with tint, rotation, exposure and an optional sun |

Then create a material, pick the shader, set its values, and drop the material into the camera's **Skybox Material** (from C#: `Camera3D.SkyboxMaterial`; changing the material's properties with `Material.SetFloat`/`SetColor`/... animates the sky). Your own sky shaders work the same way (see [Custom Shaders](Custom-Shaders.md#skybox)). A material without a Skybox shader shows a magenta sky.

Cameras saved before the sky existed have a `clearColor` but no `background` key; they load as **Solid Color**, so existing scenes look the same. New cameras, cameras whose component is reset, and cameras created from **3D Entity → Camera 3D** use the sky.

## Fog

Enable **Fog** on the Camera 3D to fade meshes into **Fog Color** with distance: nothing changes closer than **Fog Start**, and from **Fog End** on a surface is fully fog colored (smooth in between, measured from the camera in world units). Use it to hide the far end of a long level or to give depth to a valley; a fog color close to the sky's horizon color blends the level into the sky. The fog is applied after lighting and tone mapping, to lit and unlit materials, opaque and transparent ones. The sky and skybox materials are not fogged.

Untick **Fog** on a material (`"fog": false` in the `.material`) for meshes that should stay clear at any distance, e.g. a sky dome mesh, distant scenery that already has the sky's colors, or glowing goal markers. Fog is off on new cameras and on cameras saved before it existed.

```csharp
var cam = Camera3D.Main;
cam.FogEnabled = true;
cam.FogColor = new Color(0.73f, 0.83f, 0.93f, 1f);
cam.FogStart = 40f;
cam.FogEnd = 160f;
```

## Particles

**Particle System 3D** (`ParticleSystem3D`, needs a Transform 3D) emits camera-facing billboards. Create one with **3D Entity → Particle System 3D** or add the component to any 3D entity.

| Group | Fields |
|---|---|
| Particles | Play On Awake, Life Time, Speed, Size (edge length in world units), Life Time / Speed / Size **Variation** (0–1: each particle gets base × (1 ± variation)), Random Rotation, Angular Velocity (°/s), Use Gravity + Gravity (world space), Drag (fraction of velocity lost per second), Random Colors |
| Emission | Emit Over Time (particles per second, fractions accumulate), Simulation Space, **Bursts** (Count every Interval seconds, the first one right after Play) |
| Shape | **Sphere**, **Hemisphere**, **Cone** or **Box**; Radius, Cone Angle (half angle), Box Size, Emit From Surface. Cone and Hemisphere open along the entity's local **+Y**, Box emits along +Y, Sphere outwards. The shape follows the Transform 3D's rotation and scale. |
| Over Lifetime | **Scale over Lifetime** (curve) and **Color over Lifetime** (gradient, multiplied into the start color; fade out with alpha keys) |
| Rendering | Texture (none = soft round dots), Color, **Blend Mode** (Alpha for smoke and dust, Additive for fire, sparks and magic), Max Particles |

**Simulation Space World** leaves particles where they were emitted when the entity moves (trails, smoke); **Local** carries them with the entity. Particles are unlit, depth tested against meshes and drawn after all meshes; Alpha particles are sorted back to front within their system, systems are sorted by distance. The project's **Particle Quality** setting scales emission and the particle limit like it does in 2D.

In the Editor View a selected particle system shows its shape and a **Play / Restart / Stop** overlay that previews the effect without entering play mode; idle emitters show a small marker. In play mode and in games, systems with Play On Awake start by themselves (also when spawned from a prefab).

```json
"ParticleSystem3D": {
  "lifetime": 1.2, "speed": 2.5, "size": 0.4, "emitOverTime": 120,
  "shape": 2, "radius": 0.25, "coneAngle": 12,
  "color": { "r": 1, "g": 0.55, "b": 0.15, "a": 1 }, "blendMode": 1,
  "colorOverLifetimeEnabled": true,
  "colorOverLifetimeAlphaKeys": [ { "t": 0, "a": 1 }, { "t": 1, "a": 0 } ],
  "bursts": [ { "count": 30, "interval": 2 } ],
  "texture": "7100000000000000001"
}
```

Enum values in scene files: `shape` 0 Sphere, 1 Hemisphere, 2 Cone, 3 Box; `simulationSpace` 0 Local, 1 World; `blendMode` 0 Alpha, 1 Additive. Missing keys use the defaults. Curves and gradients use the same keys as Particle System 2D (`scaleOverLifetimeKeys`, `colorOverLifetimeColorKeys`, `colorOverLifetimeAlphaKeys`).

## Rendering

`Renderer3D` is a forward renderer on the same WebGPU backend as the 2D renderer. Per frame it:

1. clears the screen to the main Camera 3D's clear color and draws the sky if its background is Skybox,
2. renders the shadow map of the main directional light (if enabled),
3. draws every opaque Mesh Renderer with depth testing, instanced per (mesh, texture) pair with the material values per instance, lit by up to Max Lights lights, then the transparent ones back to front with alpha blending,
4. draws the Particle System 3D billboards (depth tested, not depth writing),
5. hands over to the 2D renderer, which draws sprites, particles and world text on top (without clearing), followed by UI.

A scene can therefore mix a 3D world with a 2D HUD: the scene's Camera 2D draws the 2D layer with its own orthographic projection (Orthographic Size, position), unaffected by the Camera 3D. When a scene has a Camera 3D, no default Camera 2D is created for it, so add one for a HUD made of sprites.

MSAA is not available: the editor views and the swap chain are single-sampled targets shared with the 2D renderer and UI, whose pipelines would all need matching sample counts and a resolve step.

## Editor

- **3D toggle** (Editor View toolbar, top right): switches the scene camera. 3D projects start in 3D mode; once toggled, the choice is saved per project (`editorView3D` in `project.json`).
- **Camera:** hold the right mouse button to orbit (add **W/A/S/D** to fly, **Q/E** down/up, **Shift** faster), hold the middle mouse button to pan, use the wheel to zoom, press **F** to frame the selected entity (also while the Entities or Inspector panel has focus).
- **Selection:** click a mesh, camera or light, or a sprite or UI element (they are drawn on the z = 0 plane, over the meshes, and win the click). Clicking the same spot again selects the next entity behind it. Ctrl/Shift-click toggles. The orange selection box surrounds every mesh the entity and its enabled children draw, turned with the entity, so selecting a character's root (an empty parent of its model) frames the whole character; **F** frames the same box. An entity that draws nothing, such as a light or an empty, gets a small box at its origin. A selected 2D entity gets an outline on that plane, and **F** frames it.
- **Gizmo:** the Move / Rotate / Scale tools work in 3D. Snapping uses the grid, rotation and scale snap settings; hold **Left Ctrl** to snap temporarily. Every drag is one undo step.
- **Create menu:** **3D Entity** offers Empty, Cube, Sphere, Plane, Cylinder, Camera 3D, Directional Light, Point Light, Spot Light and Particle System 3D. In 3D mode, **Create (Entity)** and **Camera** create 3D entities.
- **Collider gizmos:** the selected entity's 3D colliders are outlined in green (triggers in light blue): boxes, spheres and capsules as their physics shape, mesh colliders as their triangle edges (a convex custom mesh or a mesh over 20,000 triangles as its bounds). The outlines stay visible inside and behind meshes, faded where they are hidden.
- **Particle gizmos:** the selected Particle System 3D shows its emission shape (sphere, hemisphere, cone or box) and a Play / Restart / Stop overlay for an edit-mode preview.
- **Light gizmos:** point lights show a small sphere and, while selected, their range sphere; spot lights show their cone (to their range while selected, with the inner angle).
- **Sky:** the Editor View shows the background and sky ambient of the scene's main Camera 3D (a grey background when the scene has none, and in prefab edit mode).
- **Game View** renders through the scene's Camera 3D; a Camera 2D draws the 2D layer over it exactly as in builds (also in `funke editor screenshot` and the project preview).

## Scripting

```csharp
public class Mover : EntityScript
{
    private Transform3D? m_Transform;

    public override void OnStart() => m_Transform = GetComponent<Transform3D>();

    public override void OnUpdate()
    {
        Vector2 input = Input.GetAxis();
        m_Transform!.Position += new Vector3(input.X, 0.0f, -input.Y) * (4.0f * Time.DeltaTime);
    }
}
```

`Transform3D` exposes `Position`, `Rotation`, `Scale`, `WorldPosition` and `Forward`. `Camera3D.Main` returns the active 3D camera; `Camera3D` also has `Background`, `SkyTopColor`, `SkyHorizonColor`, `SkyGroundColor`, `SunSize`, `SkyAmbient`, `AmbientFromSkybox`, `SkyboxMaterial` (a `Material` or null for the gradient, e.g. `camera.SkyboxMaterial = AssetManager.Load<Material>("Materials/Night.material")`) and `FogEnabled`, `FogColor`, `FogStart`, `FogEnd`. `MeshRenderer` has `Mesh` (a `PrimitiveMesh`), `CustomMesh` (a `Mesh` asset or null), `Material`, `Color`, `Lit` and `CastShadows`. A `Mesh` (`AssetManager.Load<Mesh>("Meshes/Rock.obj")`) reports `IsValid`, `VertexCount`, `TriangleCount`, `BoundsMin` and `BoundsMax`. `PointLight` (`Color`, `Intensity`, `Range`) and `SpotLight` (plus `InnerAngle`, `OuterAngle`) work like `DirectionalLight` (`Color`, `Intensity`, `Ambient`, `CastShadows`).

```csharp
Material? gold = AssetManager.Load<Material>("Materials/Gold.material");
GetComponent<MeshRenderer>()!.Material = gold;
gold!.EmissiveIntensity = 2.0f;           // shared: every renderer using Gold changes, the file does not
RenderSettings.ShadowQuality = ShadowQualityLevel.High;
RenderSettings.Exposure = 1.2f;
```

```csharp
var sparks = GetComponent<ParticleSystem3D>()!;
sparks.Emit(60);                              // one-shot, works while stopped; uses the emitter's current position
sparks.BlendMode = ParticleBlendMode3D.Additive;
sparks.Texture = AssetManager.Load<Texture>("Textures/Spark.png");
```

`ParticleSystem3D` has `Play`, `Pause`, `Stop` (stops emitting, live particles finish), `Restart`, `Clear`, `Emit(count)`, `IsPlaying`, `ParticleCount`, and the properties `LifeTime`, `Speed`, `Size`, `EmitOverTime`, `Color`, `UseGravity`, `Gravity`, `Drag`, `AngularVelocity`, `MaxParticles`, `PlayOnAwake`, `BlendMode`, `SimulationSpace`, `Shape`, `Radius`, `ConeAngle` and `Texture`. Curves, gradients and bursts are authored in the Inspector or the scene file.

`Material` properties (`BaseColor`, `BaseColorTexture`, `Metallic`, `Roughness`, `EmissiveColor`, `EmissiveIntensity`, `Lit`, `Surface`, `Tiling`, `Offset`) change the live shared material and are not saved. `RenderSettings` (and `GraphicsSettings`) also carry `ShadowDistance`, `MaxLights` and `ToneMapping`, and the animation distance rate (`AnimationDistanceRateEnabled`, `AnimationHalfRateDistance`, `AnimationQuarterRateDistance`). Texture quality, anisotropic filtering and anti-aliasing work in 2D and 3D: see [Graphics Settings](Graphics-Settings.md).

## Not available yet

- FBX models, materials and textures from glTF files, morph targets (blend shapes), animation layers/masks and GPU skinning; normal/metallic/roughness maps, alpha-cutout materials, per-triangle transparency sorting, custom shaders.
- Shadows from point and spot lights, cascaded shadow maps, image-based (cubemap) skies and reflections.
- MSAA (see [Rendering](#rendering)).
- Lit, soft (depth-faded), stretched or mesh particles, particle collisions, sub-emitters and GPU simulation.
- 3D audio. (3D physics is covered in [Physics 3D](Physics-3D.md).)
- Post-processing on 3D (the 2D post-processing stack only processes the 2D layer).
- A quaternion API in C#; rotations are Euler degrees.
