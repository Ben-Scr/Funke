# 3D

Funke started as a 2D engine. This page covers the 3D foundation: what exists, how it fits next to 2D, and what is still missing.

## Components

| Component | Fields | Notes |
|---|---|---|
| **Transform 3D** (`Transform3D`) | Position, Rotation (Euler degrees: X pitch, Y yaw, Z roll), Scale | Local to the parent's Transform 3D. Conflicts with Transform 2D; can accompany Rect Transform 2D for a [world-space UI canvas](World-Space-UI.md). |
| **Camera 3D** (`Camera3D`) | Projection (Perspective / Orthographic), Field Of View (vertical, degrees), Orthographic Size, Near Clip, Far Clip, Background (Skybox / Solid Color), Clear Color, Skybox Material, Sky Top / Sky Horizon / Sky Ground, Sun Size, Sky Ambient, Ambient From Skybox, Fog, Fog Color, Fog Start, Fog End | Looks down its local −Z axis. The first enabled Camera 3D of the loaded scenes renders the game. See [Sky](#sky) and [Fog](#fog). |
| **Mesh Renderer** (`MeshRenderer`) | Mesh (Cube, Sphere, Plane, Cylinder), Material, Color, Lit, Cast Shadows | Built-in primitives, 1 unit in size. Plane lies flat (XZ) and faces +Y. Color tints the material. Lit only applies without a material. |
| **Skinned Mesh Renderer** (`SkinnedMeshRenderer`) | Model, Material, Color, Lit, Cast Shadows, Clip, Speed, Loop, Play On Awake, Preview In Edit Mode, Culling Mode, Distance Rate, Half / Quarter Rate From | Draws an animated glTF model and plays one of its clips. See [Skeletal animation](#skeletal-animation). Can't share an entity with a Mesh Renderer. |
| **Directional Light** (`DirectionalLight`) | Color, Intensity, Ambient, Cast Shadows | Shines along its local −Z axis. The first enabled one is the *main* light: its Ambient is the flat ambient, it draws the sun disc and it is the only light that casts shadows. |
| **Point Light** (`PointLight`) | Color, Intensity (default 4), Range (default 10) | Shines in all directions from its position and fades to zero at Range. |
| **Spot Light** (`SpotLight`) | Color, Intensity (default 6), Range (default 15), Inner Angle (default 20°), Outer Angle (default 30°) | Cone along its local −Z axis; full intensity inside Inner Angle, fading to zero at Outer Angle (both half angles). |

Every 3D component needs a Transform 3D; the editor adds it when you add them from **Add Component**. An entity holds at most one light component. A scene without any light component gets a default light from above, so meshes are never black.

World matrices come from `Transform3DHierarchySystem`, which runs before the scripts every frame. A child of an entity without a Transform 3D (for example an empty grouping entity) still inherits the transform of the nearest ancestor that has one.

Scene JSON keys: `Transform3D` (`posX/posY/posZ`, `rotX/rotY/rotZ`, `scaleX/scaleY/scaleZ`), `Camera3D` (`projection`, `fov`, `orthoSize`, `near`, `far`, `background`, `clearColor`, `skyTop`, `skyHorizon`, `skyGround`, `sunSize`, `skyAmbient`, `fog`, `fogColor`, `fogStart`, `fogEnd`), `MeshRenderer` (`mesh` 0–3, `customMesh`, `material`, `color`, `lit`, `castShadows`), `SkinnedMeshRenderer` (`model`, `material`, `color`, `lit`, `castShadows`, `clip`, `speed`, `loop`, `playOnAwake`, `previewInEditMode`, and only when changed `cullingMode`, `distanceRate`, `halfRateDistance`, `quarterRateDistance`), `DirectionalLight` (`color`, `intensity`, `ambient`, `castShadows`), `PointLight` (`color`, `intensity`, `range`), `SpotLight` (`color`, `intensity`, `range`, `innerAngle`, `outerAngle`). Missing keys take the defaults, so scenes saved before these fields existed still load.

## Materials

The [3D workflow report](3D-Asset-Workflow-Verification.md) records the D3D12 comparisons across Edit, Play and stripped export, including live image reimport.

A material is a `.material` asset: a small JSON file with a GUID in its `.meta`, like every other asset. Its **Shader** field can pick your own `.wgsl` shader instead of the standard PBR shader described here; see [Custom Shaders](Custom-Shaders.md). Create one with **Create → Material** in the Asset Browser, select it to edit it in the Inspector (every change is saved to the file right away), and drag it onto a Mesh Renderer's **Material** slot or pick it there.

| Field | Default | Meaning |
|---|---|---|
| Lit | on | Off ignores lights, exposure and tone mapping and shows Base Color (plus emissive) exactly. |
| Surface | Opaque | **Transparent** blends; **Cutout** discards coverage below Alpha Cutoff in both color and shadow passes. |
| Base Color | white | sRGB color; its alpha is the opacity of a Transparent material. |
| Base Color Texture | none | Texture asset multiplied into Base Color; sampled with repeat wrapping (point filtering if the texture's import filter is Point, linear otherwise). |
| Normal Texture / Normal Strength | none / 1 | Tangent-space RGB normal map, sampled as linear data. Missing maps preserve the geometric normal. |
| Metallic / Roughness Texture | none | Linear packed map: green multiplies Roughness, blue multiplies Metallic. |
| Emissive Texture | none | sRGB image multiplied by Emissive Color and Intensity. |
| Occlusion Texture / Strength | none / 1 | Linear red channel attenuates indirect lighting. |
| Alpha Cutoff | 0.5 | Cutout coverage threshold; surviving pixels write depth. |
| Double Sided | off | Draw both faces; reverse the back-face shading normal. |
| Metallic | 0 | 0 = plastic/wood/stone, 1 = metal. |
| Roughness | 0.5 | 0 = mirror-like highlight, 1 = fully matte. |
| Emissive Color / Intensity | black / 1 | Light the surface gives off itself (not lighting other objects). |
| Tiling / Offset | (1,1) / (0,0) | UV scale and shift of the texture. |

On disk (`Assets/Materials/Gold.material`):

```json
{
  "type": "Material", "version": 1, "lit": true, "surface": 0,
  "baseColor": { "r": 1.0, "g": 0.78, "b": 0.34, "a": 1.0 },
  "baseColorTexture": "0",
  "metallic": 1.0, "roughness": 0.3,
  "emissiveColor": { "r": 0, "g": 0, "b": 0, "a": 1 }, "emissiveIntensity": 1.0,
  "tiling": { "x": 1, "y": 1 }, "offset": { "x": 0, "y": 0 }
}
```

GUIDs (`baseColorTexture` here, `material` in the scene) are written as decimal strings. All Mesh Renderers that use a material share it: editing the file (in the editor or outside it) updates all of them. A primitive or OBJ mesh without imported materials or overrides uses a white default material (metallic 0, roughness 0.5) tinted by its Color, and its own Lit flag. Build asset pruning keeps every material a shipped scene references and every texture such a material references.

### Transparency

A material with **Surface = Transparent** (`"surface": 1`) is alpha blended. Its opacity is Base Color alpha × texture alpha × the Mesh Renderer's Color alpha, so one glass material can be made more or less see-through per renderer. Transparent meshes are drawn after all opaque ones, sorted per object from the farthest to the nearest (by the centre of the mesh bounds), with depth testing but without writing depth. Lighting, emissive and unlit materials work as for opaque surfaces. Lit transparent surfaces follow Fresnel: reflected light is not filtered by the transparency, so the surface turns more opaque and mirror-like at grazing angles — a low roughness (≈ 0.03) gives water and glass a clear sky reflection.

Limits: sorting is per object, so two transparent meshes that intersect, or one large concave transparent mesh, can show parts in the wrong order. Only front faces are drawn unless **Double Sided** is enabled. A transparent mesh with **Cast Shadows** on casts a full (opaque) shadow; turn it off for glass.

## Custom meshes

Besides the built-in primitives a Mesh Renderer can draw a mesh asset: drop a Wavefront `.obj` or a glTF 2.0 file (`.gltf`, `.glb`) into `Assets/` and pick it in the renderer's **Custom Mesh** slot (`"customMesh": "<guid>"` in the scene). While a custom mesh is set the primitive **Mesh** field is ignored; clearing the slot draws the primitive again.

- glTF: triangle geometry is combined with separate draw ranges and primitive material assignments. A Mesh Renderer draws the rest pose; a Skinned Mesh Renderer plays animation. Buffers and images may be external, data URIs or GLB buffer views. With no renderer Material override each primitive uses its imported standard PBR material; an explicit `.material` overrides the whole model. Imported materials/images initially belong to the model asset. Per-slot overrides and explicit extraction into editable assets are available in the renderer Inspector. Cameras, lights and morph targets remain ignored.
- Read from an OBJ file: positions, texture coordinates and normals (`v`, `vt`, `vn`, `f`); faces with more than three corners are triangulated, negative (relative) indices work, and all objects and groups in the file become one mesh. `usemtl` starts a new draw range when the next face changes material. Each `mtllib` line accepts one relative MTL path, including spaces. Lines and points are ignored.
- Missing normals are computed as smooth normals per position; missing texture coordinates are 0.
- Faces should wind counter-clockwise seen from outside (the OBJ convention); back faces are culled. The mesh keeps the file's units and origin — scale it with the Transform 3D.
- A file that cannot be read draws nothing and logs a warning; fixing the file reloads it, and edits made outside the editor reload live. Picking, the selection box and **F** (frame) use the mesh's bounds.
- **Mesh Collider 3D** collides with the custom mesh of the entity's Mesh Renderer (**Use Mesh Renderer**), or with its own **Custom Mesh**.

### Material slots and editable copies

Mesh Renderer and Skinned Mesh Renderer expose **Model Materials** for a single
selected entity. Each used slot accepts a `.material`; **None** restores the
source model material. The renderer's top-level **Material** field overrides
all slots and takes precedence. Slot overrides are serialized with the renderer
in scenes/prefabs and their material/texture dependencies survive asset stripping.

**Extract Editable Materials** creates `.material` and PNG copies under
`Assets/ImportedMaterials/<model-guid>/`, then fills currently unassigned slots.
Existing files, import settings and explicit slot overrides are preserved.
The assignment can be undone; the created asset files remain. Reimporting or
extracting again does not overwrite edits to these user-owned copies. Clear a
slot override to use the current source material again.

Material filenames depend on the model GUID and material key; existing `.meta`
GUIDs are reused. Within that model directory, identical decoded images with
identical filter/wrap settings share a PNG. Different sampler settings produce
separate texture assets. Renaming/moving extracted files ends their automatic
reuse by the extraction button; explicitly assigned GUID references still work.

Unique, nonempty glTF material names keep slot identity when source materials
are reordered. Renaming a source material changes its identity. Unnamed or
repeated names fall back to source indices, so keep their order stable. Overrides
are bound to one model GUID and cannot apply to another model merely because
it has the same material names. Existing scenes without overrides keep their
previous behavior.

C# exposes the same slot operations on both renderer types. Attach this example to a Mesh Renderer whose glTF model has a material named `Body`. Assign a `.material` to the script’s Override field to replace that slot. Leave it empty to restore the imported material.

```csharp
using Funke;

public class BodyMaterial : EntityScript
{
    public Material? Override;

    public override void OnStart()
    {
        if (GetComponent<MeshRenderer>() is not { } renderer)
            return;

        for (int slot = 0; slot < renderer.MaterialSlotCount; ++slot)
        {
            if (renderer.GetMaterialSlotName(slot) == "Body")
                renderer.SetMaterialOverride(slot, Override);
        }
    }
}
```

`MaterialSlotCount` includes unused source materials. glTF includes its implicit default slot. OBJ exposes named materials and a default when faces need one. Primitives and plain geometry-only OBJ files return zero. Invalid indices throw
`ArgumentOutOfRangeException`. Scene overrides use full-width GUID strings.
Use matching Engine, Editor, Runtime and ScriptCore binaries for the slot APIs. See the [binding contract](../Scripting/Binding-Contracts.md) and [3D workflow verification](3D-Asset-Workflow-Verification.md).

### Imported material limits

The importer supports `TEXCOORD_0`; a texture requesting another UV set or
`KHR_texture_transform` is rejected with a diagnostic. Required extensions
other than `KHR_materials_unlit` are rejected; optional unsupported extensions
use the base glTF fallback. Clamp/repeat/mirror wrapping is retained; the
engine filter enum approximates glTF combinations that specify different
minification and magnification filters.

Authored `TANGENT` data survives node transforms and CPU/GPU skinning. Without
it the standard shader derives a tangent frame from UV derivatives, including
mirrored UVs; degenerate UVs keep the geometric normal. This fallback is not
MikkTSpace tangent generation. Native `MeshVertex` now occupies 48 bytes
(position, normal, UV, tangent/handedness); rebuild native consumers together.

An external image edit reloads its model. A failed decode keeps the last valid
model while the file is repaired. Renderer material overrides remain in the
scene and take precedence across reimports. Individual imported material slot
overrides and extraction into editable assets remain open.

### Meshes built from code

`Mesh.Create()` returns an empty in-memory mesh for geometry a script computes: procedural terrain, a water surface from a fluid simulation, trails. Fill it with `SetData` and assign it like a mesh asset:

```csharp
Mesh surface = Mesh.Create();
GetComponent<MeshRenderer>()!.CustomMesh = surface;

// Any time, as often as every frame: replaces the whole geometry.
surface.SetData(positions, indices);              // ReadOnlySpan<Vector3>, ReadOnlySpan<int> (triangle list)
surface.SetData(positions, indices, normals, uvs); // optional per-vertex normals and UVs
```

- Positions are in the entity's local space; indices are a triangle list wound counter-clockwise seen from outside (back faces are culled). Without normals, smooth normals are computed from the triangles; without UVs they are 0.
- `SetData` throws `ArgumentException` when normals/UVs don't match the vertex count or an index is out of range, and `InvalidOperationException` on a mesh asset or a destroyed mesh. `Clear()` removes all geometry (the renderer draws nothing), `Destroy()` frees the mesh; runtime meshes still alive when Play mode ends are freed then. `IsRuntime` tells them apart from `.obj` assets.
- Rewriting a mesh every frame is cheap: its GPU buffers only grow and are rewritten in place. Lists of vertices can be passed without copying via `CollectionsMarshal.AsSpan(list)`.
- Runtime meshes are not saved: a scene stores the renderer's primitive **Mesh**, so author a placeholder primitive (e.g. a Plane where the water will be) for the Editor View and assign the runtime mesh in `OnStart`.
- A Mesh Collider 3D can use a runtime mesh too; it rebuilds its shape whenever the geometry changes, which is expensive for large meshes updated every frame.

Build asset pruning keeps referenced mesh and skinned-model assets, including external buffer and image files used by glTF models.

## Skeletal animation

A **Skinned Mesh Renderer** draws an animated glTF model (`.glb` or `.gltf`, exported for example from Blender with *Skinning* and *Animation* enabled) and plays its clips:

1. Drop the model into `Assets/` and pick it in **Model**. The inspector lists the model's clips under **Pick Clip** with their length, plus its vertex, node, joint and clip counts.
2. Leave **Clip** empty to play the first clip, or pick or type a clip name. **Speed** scales playback (negative plays backwards), **Loop** repeats the clip, otherwise it holds its last frame.
3. **Play On Awake** starts the clip when Play begins. In edit mode the renderer shows the clip's first frame; **Preview In Edit Mode** plays it in the editor too.

How it works:

- Skins (up to four joint weights per vertex) and node animation both animate: rigid parts parented to an animated node (a robot arm, a door) move with that node. Translation, rotation and scale channels are read with Linear, Step and Cubic Spline interpolation.
- Animation poses and joint matrices are evaluated on the CPU; vertex skinning uses a GPU compute pass when the model fits the device's limits, with a CPU fallback. The posed mesh goes through the regular mesh pass, so materials, custom shaders, transparency, fog and shadows work as on a Mesh Renderer. A model is re-posed only when its pose changes. Profile the actual model and character count on the target device.
- **Culling Mode** and **Distance Rate** work as on the Animator (see [Animation > Culling and distance rate](Animation.md#culling-and-distance-rate)): off screen (Cull Pose) or far from the camera, the model keeps its last skinned pose and is re-skinned only on its update frames, every 2nd or 4th frame. The play head itself keeps the exact time, so `Time`, `IsPlaying` and the end of a one-shot clip stay right for scripts. Off screen means outside the camera's view with the model's rest-pose bounds plus a margin.
- Picking, the selection box and **F** use the bounds of the pose the model is drawn in (the clip's first frame in edit mode, the current frame while it plays).

From a script:

```csharp
using Funke;

public class PlayerAnimation : EntityScript
{
    private SkinnedMeshRenderer? m_Model;

    public override void OnStart() => m_Model = GetComponent<SkinnedMeshRenderer>();

    public override void OnUpdate()
    {
        bool moving = Input.GetAxis().Length() > 0.1f;
        m_Model!.Play(moving ? "Run" : "Idle", crossFade: 0.2f);
    }
}
```

`Play(clip, crossFade = 0.2f)` blends from the current pose to the new clip over `crossFade` seconds; calling it again for the clip that is already playing does nothing, so it is safe to call every frame. `Pause()`, `Resume()` and `Stop()` (back to the first frame) control playback; `Clip`, `IsPlaying`, `Time`, `Speed`, `Loop`, `PlayOnAwake`, `ClipNames` and `GetClipLength(name)` read or change it. `TryGetBone("Hand.R", out position, out forward, out up)` returns a bone's (or any model node's) world position and axes in the drawn pose, e.g. to place a sword in a hand every frame; while culling or the distance rate holds the pose back, the bone stays with the drawn model. `Model`, `Material`, `Color`, `Lit` and `CastShadows` work like on a Mesh Renderer; `CullingMode`, `DistanceRate`, `HalfRateDistance` and `QuarterRateDistance` like on the Animator.

## Lights and shading

Lighting is physically based (GGX/Cook-Torrance specular with Lambert diffuse) and runs in linear color space: colors you pick are sRGB and converted before lighting. A white light with intensity 1 lights a white surface facing it to full brightness.

- **Directional lights** have no falloff. **Point and spot lights** fall off with the inverse square of the distance, smoothly windowed so they reach exactly zero at Range. Intensity is therefore "brightness at about one unit away"; raise it or the range for larger rooms.
- **Ambient:** the main directional light's Ambient color is added everywhere. With a sky background, the sky colors add hemispheric ambient (top color from above, ground color from below), scaled by the camera's **Sky Ambient**; metals reflect the sky with it. With a Skybox Material, **Ambient From Skybox** takes these colors from the material instead: a Gradient Sky's top/horizon/ground colors, the averaged upper, middle and lower band of a Panoramic Sky's image (× tint × exposure), or a 6-Sided Sky's up, side and down faces (× their colors × exposure). Texture averages are computed once per texture (`ambientFromSkybox` in scenes).
- **Light limit:** each frame uses at most **Max Lights** lights (Project Settings → Graphics → 3D Rendering, default 16, at most 64). Directional lights come first, then the point and spot lights whose range is closest to the camera.
- **Shadows:** the main directional light casts shadows from every Mesh Renderer with **Cast Shadows** on, onto everything within **Shadow Distance** of the camera (default 40 units). The shadow map is soft-edged (3×3 PCF) and fades out at the distance limit. **Shadow Quality** picks the map size (Off, Low 1024, Medium 2048, High 4096). Point and spot lights do not cast shadows.
- **Exposure** and **Tone Mapping** (None, Reinhard, ACES — default ACES) map the lit result to the screen. They do not affect unlit materials or the sky.

## Sky

New Camera 3Ds use **Background = Skybox**: a procedural gradient (Sky Top above, Sky Horizon at the horizon, Sky Ground below) drawn behind all meshes, with a sun disc in the direction of the main directional light, tinted by its color. **Sun Size** is the disc's angular radius in degrees (0 hides it). No texture is needed. **Solid Color** clears to Clear Color instead and also turns off the sky ambient.

**Skybox Material:** assign a `.material` whose shader targets `Skybox` and the camera draws it instead of the gradient (the gradient colors still drive the sky ambient). **Create → Skybox Shader** in the Project panel writes one of three ready-made shaders into the folder:

| Shader | What it shows |
|---|---|
| **Gradient Sky** | The gradient above as a material (top / horizon / ground, curve, sun on or off) |
| **6-Sided Sky** | A cube: per face (front = −Z, back, left, right, up, down) a texture times a color, so a face can be a plain color; rotation and exposure |
| **Panoramic Sky** | An equirectangular (2:1) image around the camera with tint, rotation, exposure and an optional sun |

Then create a material, pick the shader, set its values, and drop the material into the camera's **Skybox Material** (from C#: `Camera3D.SkyboxMaterial`; changing the material's properties with `Material.SetFloat`/`SetColor`/... animates the sky). Your own sky shaders work the same way (see [Custom Shaders](Custom-Shaders.md#skybox)). A material without a Skybox shader shows a magenta sky.

Cameras saved before the sky existed have a `clearColor` but no `background` key; they load as **Solid Color**, so existing scenes look the same. New cameras, cameras whose component is reset, and cameras created from **3D Entity → Camera 3D** use the sky.

## Fog

Enable **Fog** on the Camera 3D to fade meshes into **Fog Color** with distance: nothing changes closer than **Fog Start**, and from **Fog End** on a surface is fully fog colored (smooth in between, measured from the camera in world units). Use it to hide the far end of a long level or to give depth to a valley; a fog color close to the sky's horizon color blends the level into the sky. The fog is applied after lighting and tone mapping, to lit and unlit materials, opaque and transparent ones. The sky and skybox materials are not fogged.

Untick **Fog** on a material (`"fog": false` in the `.material`) for meshes that should stay clear at any distance, e.g. a sky dome mesh, distant scenery that already has the sky's colors, or glowing goal markers. Fog is off on new cameras and on cameras saved before it existed.

```csharp
var cam = Camera3D.Main;
cam.FogEnabled = true;
cam.FogColor = new Color(0.73f, 0.83f, 0.93f, 1f);
cam.FogStart = 40f;
cam.FogEnd = 160f;
```

## Particles

**Particle System 3D** (`ParticleSystem3D`, needs a Transform 3D) emits camera-facing billboards. Create one with **3D Entity → Particle System 3D** or add the component to any 3D entity.

| Group | Fields |
|---|---|
| Particles | Play On Awake, Life Time, Speed, Size (edge length in world units), Life Time / Speed / Size **Variation** (0–1: each particle gets base × (1 ± variation)), Random Rotation, Angular Velocity (°/s), Use Gravity + Gravity (world space), Drag (fraction of velocity lost per second), Random Colors |
| Emission | Emit Over Time (particles per second, fractions accumulate), Simulation Space, **Bursts** (Count every Interval seconds, the first one right after Play) |
| Shape | **Sphere**, **Hemisphere**, **Cone** or **Box**; Radius, Cone Angle (half angle), Box Size, Emit From Surface. Cone and Hemisphere open along the entity's local **+Y**, Box emits along +Y, Sphere outwards. The shape follows the Transform 3D's rotation and scale. |
| Over Lifetime | **Scale over Lifetime** (curve) and **Color over Lifetime** (gradient, multiplied into the start color; fade out with alpha keys) |
| Rendering | Texture (none = soft round dots), Color, **Blend Mode** (Alpha for smoke and dust, Additive for fire, sparks and magic), Max Particles |

**Simulation Space World** leaves particles where they were emitted when the entity moves (trails, smoke); **Local** carries them with the entity. Particles are unlit, depth tested against meshes and drawn after all meshes; Alpha particles are sorted back to front within their system, systems are sorted by distance. The project's **Particle Quality** setting scales emission and the particle limit like it does in 2D.

In the Editor View a selected particle system shows its shape and a **Play / Restart / Stop** overlay that previews the effect without entering play mode; idle emitters show a small marker. In play mode and in games, systems with Play On Awake start by themselves (also when spawned from a prefab).

```json
{
  "ParticleSystem3D": {
    "lifetime": 1.2, "speed": 2.5, "size": 0.4, "emitOverTime": 120,
    "shape": 2, "radius": 0.25, "coneAngle": 12,
    "color": { "r": 1, "g": 0.55, "b": 0.15, "a": 1 }, "blendMode": 1,
    "colorOverLifetimeEnabled": true,
    "colorOverLifetimeAlphaKeys": [ { "t": 0, "a": 1 }, { "t": 1, "a": 0 } ],
    "bursts": [ { "count": 30, "interval": 2 } ],
    "texture": "7100000000000000001"
  }
}
```

Enum values in scene files: `shape` 0 Sphere, 1 Hemisphere, 2 Cone, 3 Box; `simulationSpace` 0 Local, 1 World; `blendMode` 0 Alpha, 1 Additive. Missing keys use the defaults. Curves and gradients use the same keys as Particle System 2D (`scaleOverLifetimeKeys`, `colorOverLifetimeColorKeys`, `colorOverLifetimeAlphaKeys`).

## Rendering

`Renderer3D` is a forward renderer on the same WebGPU backend as the 2D renderer. Per frame it:

1. clears the screen to the main Camera 3D's clear color and draws the sky if its background is Skybox,
2. renders the shadow map of the main directional light (if enabled),
3. draws every opaque Mesh Renderer with depth testing, instanced per (mesh, texture) pair with the material values per instance, lit by up to Max Lights lights, then the transparent ones back to front with alpha blending,
4. draws the Particle System 3D billboards (depth tested, not depth writing),
5. hands over to the 2D renderer, which draws sprites, particles and world text on top (without clearing), followed by UI.

A scene can therefore mix a 3D world with a 2D HUD: the scene's Camera 2D draws the 2D layer with its own orthographic projection (Orthographic Size, position), unaffected by the Camera 3D. When a scene has a Camera 3D, no default Camera 2D is created for it, so add one for a HUD made of sprites.

**MSAA 4x** renders the 3D scene into a multisampled target and resolves it before the 2D layer and UI. **FXAA** is also available. A Post Processing component on the Camera 3D applies the shared post-processing effects, including custom WGSL effects, to the 3D image. See [Graphics Settings](Graphics-Settings.md#anti-aliasing) and [Custom Shaders](Custom-Shaders.md).

## Editor

- **3D toggle** (Editor View toolbar, top right): switches the scene camera. 3D projects start in 3D mode; once toggled, the choice is saved per project (`editorView3D` in `project.json`).
- **Camera:** hold the right mouse button to orbit (add **W/A/S/D** to fly, **Q/E** down/up, **Shift** faster), hold the middle mouse button to pan, use the wheel to zoom, press **F** to frame the selected entity (also while the Entities or Inspector panel has focus).
- **Selection:** click a mesh, camera, light, sprite or UI element. The 2D overlay is drawn on the z = 0 plane; world-space canvases use their own world transforms (see [World-space UI](World-Space-UI.md)). Clicking the same spot again selects the next entity behind it. Ctrl/Shift-click toggles. The orange selection box surrounds every mesh the entity and its enabled children draw, turned with the entity, so selecting a character's root (an empty parent of its model) frames the whole character; **F** frames the same box. An entity that draws nothing, such as a light or an empty, gets a small box at its origin. A selected 2D entity gets an outline on that plane, and **F** frames it.
- **Gizmo:** the Move / Rotate / Scale tools work in 3D. Snapping uses the grid, rotation and scale snap settings; hold **Left Ctrl** to snap temporarily. Every drag is one undo step.
- **Ground grid:** the world-aligned XZ raster has smoothed lines even with anti-aliasing disabled. Fine and major lines blend between detail levels as their screen spacing changes, and fade out toward the distance and outer edge. The red X and blue Z axes remain at the world origin; visual grid detail does not change the snapping settings.
- **Create menu:** **3D Entity** offers Empty, Cube, Sphere, Plane, Cylinder, Camera 3D, Directional Light, Point Light, Spot Light and Particle System 3D. In 3D mode, **Create (Entity)** and **Camera** create 3D entities.
- **Collider gizmos:** the selected entity's 3D colliders are outlined in green (triggers in light blue): boxes, spheres and capsules as their physics shape, mesh colliders as their triangle edges (a convex custom mesh or a mesh over 20,000 triangles as its bounds). The outlines stay visible inside and behind meshes, faded where they are hidden.
- **Particle gizmos:** the selected Particle System 3D shows its emission shape (sphere, hemisphere, cone or box) and a Play / Restart / Stop overlay for an edit-mode preview.
- **Light gizmos:** point lights show a small sphere and, while selected, their range sphere; spot lights show their cone (to their range while selected, with the inner angle).
- **Camera gizmo:** a selected Camera 3D shows its view volume from Near Clip to Far Clip at the Game View's aspect ratio (perspective: a frustum, orthographic: a box of Orthographic Size half height). Other cameras show a short piece of it with a triangle on top marking the camera's up side.

- **Game View** renders through the scene's Camera 3D; a Camera 2D draws the 2D layer over it exactly as in builds (also in `funke editor screenshot` and the project preview).

## Quaternion rotations in C#

`Quaternion` stores four floats in **X, Y, Z, W** order (16 bytes). `Identity` is `(0, 0, 0, 1)`. The rotation methods normalize their inputs; zero/default and nonfinite quaternions become Identity. Raw fields and equality retain their exact values, so opposite signs compare unequal even when they represent the same rotation.

`AngleAxis(degrees, axis)`, `Euler(x, y, z)` and `EulerAngles` use **degrees**. Euler angles match native GLM: X pitch, Y yaw, Z roll, applying X then Y then Z. `a * b` applies **b first, then a**. `rotation * vector` / `RotateVector` rotate a vector in the right-handed coordinate system with local **-Z forward**. `Inverse` returns the inverse normalized rotation; `Slerp` takes the shortest arc, clamps finite t to 0–1, and selects its first input for nonfinite t.

`LookRotation(forward, up)` aligns local -Z to forward. A missing, nonfinite or parallel up vector uses a deterministic perpendicular basis; an invalid/zero forward returns Identity. Zero or nonfinite AngleAxis inputs and nonfinite Euler angles also return Identity. `Normalize` and `Normalized` handle very large and very small finite components without float norm overflow.

```csharp
var transform = GetComponent<Transform3D>()!;
transform.LocalRotation = Quaternion.Euler(0, 45, 0);
transform.WorldRotation = Quaternion.LookRotation(targetDirection);
transform.LocalRotation = Quaternion.Slerp(transform.LocalRotation, desiredLocalRotation, 0.1f);
```

`Transform3D.Rotation` remains the existing **local Euler-degree** property and the scene/prefab serialization format is unchanged. `LocalRotation` converts through those angles. `WorldRotation` composes current ancestor rotations, including ancestors above entities without Transform3D; its setter computes the corresponding local rotation without changing parents. It does not wait for cached world matrices, and intentionally excludes scale, reflection and shear, which do not define a unique quaternion orientation. Cycles or more than 1024 ancestors produce an explicit exception. Euler round-trips preserve orientation within floating-point tolerance, not necessarily the original three angle values.

## C# movement and coordinate utilities

### Rotation, surface normals and movement

`SetLocalPose(position, rotation)` validates both fields before writing on
the engine thread and preserves scale. `GetWorldPose()` returns current
world position and composed quaternion orientation. `TrySetWorldPose`
validates and converts both values before writing and rejects a singular
parent or invalid rotation. These helpers leave the cached rendering pose
untouched when reading.

In a Windows player test, a parent at (3,2,-1) with 90° yaw transformed
local (2,0,0) to (3,2,-3). A further 90° orbit reached (1,2,-1). A Jolt
raycast identified the spawned sphere collider there. The moved static
mesh's red region at the second capture was centered near (962,369),
versus (776,478) in a control run retaining the original pose (1920×1080).
The other red mesh remained centered near (783,630) in both runs.

`TransformUtility.TryLookAt3D(originWorld, targetWorld, up, out rotation)`
computes the orientation of local -Z. Coincident points or nonfinite inputs
return false. A parallel up direction selects a perpendicular basis.
`FaceTowards3D` limits angular travel to degrees per second times the supplied
elapsed seconds. `FaceOnPlane3D` projects the target direction onto a world
plane and returns false when no direction remains. Both write the current
world orientation, including under rotated parents. Reflection and shear
still affect the rendered geometry. `RotatePoint3D` takes a world pivot and
axis. `DirectionTo3D` returns a unit direction or zero.

`TransformNormal` applies the inverse transpose of the current world matrix
and normalizes the result. Use it for a mesh surface normal under nonuniform
scale, including sheared hierarchies. A singular matrix throws
`InvalidOperationException`. A zero normal has no direction.

`Vector3` supplies squared distance, unclamped lerp, projection onto a vector
or plane, reflection, signed and unsigned angles in degrees, and
`TryNormalize`. A zero projection axis yields zero projection. Quaternion
`FromToRotation` handles opposite directions. `Angle` treats opposite
quaternion signs as the same rotation. `RotateTowards` caps each step.
`Mathf.MoveTowardsAngle` and `SmoothDampAngle` return degrees in [0,360)
and use the shortest arc. `Repeat` wraps negative inputs and `PingPong` folds
them across a positive length. Scalar and Vector2 `SmoothDamp` share the
Vector3 critical-damping and persistent-velocity contract. Scalar, Vector3
and Quaternion `Damp` take a nonnegative rate and elapsed seconds. With a
stationary target, the remaining fraction after t seconds is exp(-rate × t).

### Geometry, sampling and debug drawing

Construct `new Bounds3D(mesh.BoundsMin, mesh.BoundsMax)` for a mesh's local
bounds. Supply world-space endpoints for a world-space box. Contains and
Intersects include touching faces. ClosestPoint clamps all three coordinates.
Encapsulate and Expand return a new box. Expand grows each face by the
specified distance. Bounds3D.TryRaycast and Ray.TryIntersectSphere report
the first forward hit in world units and return distance zero when starting
inside. Vector3.ClosestPointOnSegment handles coincident endpoints.

Seeded `Funke.Random` supplies uniform area/volume sampling
(`InsideUnitCircle`, `InsideUnitSphere`), uniform directions (`OnUnitSphere`)
and orientations (`UniformRotation`). `WeightedIndex` takes finite,
nonnegative weights with positive total. `Shuffle` permutes a span in place.

`Gizmo.DrawRay`, `DrawArrow`, `DrawAxes`, `DrawCapsule` and `DrawFrustum`
use the existing depth-tested world-space primitives and shared vertex budget.
Axes use the active gizmo color and the logical right, up and forward axes.
Capsule endpoints specify hemisphere centers. Frustum corners are supplied
as two matching cyclic world-space loops of four points.

`Aiming3D.InViewCone` takes a half-angle in degrees and a maximum range.
`LaunchVelocity` solves for arrival at a chosen time under constant world
acceleration. `TryIntercept` finds the earliest nonnegative hit for a
straight, constant-speed projectile and a target with constant world
velocity. All three calculations are independent of physics state.
`HasClearLine` queries the live Jolt scene over the finite segment. Pass
only obstructing layers and opt into triggers when appropriate.

`Vector3.MoveTowards(current, target, maxDelta)` takes a nonnegative distance per call and does not overshoot. `Vector3.ClampMagnitude(vector, maxLength)` preserves shorter vectors and the direction of longer ones. Both reject nonfinite inputs and negative limits, and use double intermediates to avoid float length overflow.

`Vector3.SmoothDamp(current, target, ref velocity, smoothTime, deltaTime, maxSpeed = float.PositiveInfinity)` takes **seconds** and an explicit timestep; retain `velocity` between updates and reset it after teleports. It uses an analytic critically damped spring with `omega = 2 / max(smoothTime, 0.0001)` and clips motion that passes the target along the approach direction. Zero `deltaTime` preserves both position and velocity. Negative/nonfinite time or vector inputs are rejected before updating velocity. `maxSpeed` limits the tracking offset to `maxSpeed * smoothTime` (using the clamped smooth time); it is not a hard speed cap on an externally supplied velocity. The default is unlimited.

```csharp
Vector3 next = Vector3.MoveTowards(current, target, speed * Time.DeltaTime);
Vector3 limitedInput = Vector3.ClampMagnitude(inputDirection, 1);
Vector3 smoothed = Vector3.SmoothDamp(current, target, ref velocity,
    smoothTime: 0.2f, deltaTime: Time.DeltaTime, maxSpeed: 10);
```

`TransformUtility` supplies extension methods on `Transform3D`, available with `using Funke;`. Call them on the engine thread. They compose the current local transforms through the ancestor chain, including ancestors above entities without a transform, rather than reading the world-matrix cache. Each call walks the hierarchy; use the native query/update paths for large repeated batches. These helpers do not update the render cache or perform physics movement.

| API | Contract |
| --- | --- |
| `GetWorldPosition()` | Current composed world position. The existing `WorldPosition` property still reports the last hierarchy update. |
| `SetWorldPosition(position)` / `TrySetWorldPosition(position)` | Converts through the inverse current parent matrix; the Try variant returns false without writing for a singular matrix/nonfinite result. Invalid arguments or detached components still throw. |
| `TransformPoint` / `InverseTransformPoint` | Includes translation, rotation, scale and any parent-induced shear. |
| `TransformVector` / `InverseTransformVector` | Includes the linear transform (scale/shear/rotation), excluding translation. |
| `TransformDirection` / `InverseTransformDirection` | Quaternion rotation only; ignores scale/reflection/shear and preserves length. |
| `Translate(displacement, Space.Local)` | Local axes rotated into world orientation, with distance in world units unaffected by scale. `Space.World` uses the supplied world displacement. |
| `Rotate(eulerDegrees, Space.Local)` / `Rotate(axis, degrees, Space.Local)` | Composes a rotation delta on local axes; `Space.World` applies a world delta. |
| `RotateAround(pivot, axis, degrees)` | World-space pivot and axis; rotates position and orientation together. A singular parent prevents either write. |

Inverse point/vector transforms throw for singular matrices. Full matrix composition uses System.Numerics row-vector `S * R * T`, corresponding to the transpose of native GLM's `T * R * S`. Orientation uses the same quaternion convention as `WorldRotation`; under reflected/sheared hierarchies it can differ from the cached `Forward` matrix axis. Cycles/excessive depth are bounded at 1024 ancestors.

```csharp
transform.Translate(Vector3.Forward * speed * Time.DeltaTime);
transform.Rotate(Vector3.Up, 90 * Time.DeltaTime, Space.World);
transform.RotateAround(pivotWorld, Vector3.Up, 30 * Time.DeltaTime);
Vector3 muzzleWorld = transform.TransformPoint(localMuzzleOffset);
TransformUtility.Face3D(transform, targetWorld);
```

`TransformUtility.LookAt3D(transform, targetWorld, up)` computes a world quaternion; `Face3D` writes it through `WorldRotation`. Up is optional and defaults to world +Y; local -Z faces the target. A coincident target preserves orientation, while parallel/zero up uses `Quaternion.LookRotation`'s perpendicular fallback. Nonfinite target/up is rejected. Direct transform movement is intended for script-owned transforms, not dynamic rigidbody motion.

## C# mouse picking

`Plane(normal, point)` represents `Dot(Normal, worldPoint) + Distance = 0` with a normalized normal. `TryRaycast(ray, out distance)` returns false for parallel/invalid rays or hits behind the origin; an intersection at distance zero is valid. A default plane is invalid.

```csharp
Plane ground = new(Vector3.Up, Vector3.Zero);
if (CameraUtility.TryGetMouseWorldPosition3D(ground, out Vector3 point))
    TransformUtility.Face3D(transform, point);

if (CameraUtility.TryPickMouse3D(out Funke.Physics.RaycastHit3D hit,
    maxDistance: 250, layers: Funke.PhysicsLayer.All, includeTriggers: false))
    Log.Info(hit.Entity.Name);
```

Both helpers have overloads taking a camera first; the overloads above use `Camera3D.Main`. `TryScreenPointToWorld3D(camera, screenPoint, plane, out point)` also handles explicit viewport coordinates, e.g. touch positions. Null/missing cameras or projection failure return false, as do absent plane/physics intersections. Detached component wrappers remain invalid API usage and throw. Collider picking uses the existing active-scene Physics3D query in Play mode, with body-owner layer masks and explicit trigger inclusion.

`GetMouseRay3D(camera)` and its main-camera overload throw when projection is unavailable. For nonthrowing projection use `Camera3D.TryScreenPointToRay(screenPoint, out ray)`. Viewport pixels originate at the top-left. The ray starts on the **near plane**; ray distance is not camera-space Z depth. The projection wrapper validates native origin/direction before constructing a ray, so failed/invalid queries cannot become hits from a fallback direction.

The formerly empty `GetWorldMousePosition3D()` / `(Camera3D)` helpers now return the closest non-trigger collider hit within 1000 units from the near plane and throw `InvalidOperationException` when no hit is available. Use the Try APIs when absence is normal. A successful hit at `(0, 0, 0)` is valid and distinguishable from failure.

Managed tests in `Utility3DTests.cs` cover stationary-target damping at 30/60/144 Hz, current hierarchy reads, mirrored/nonuniform scales, sheared point/vector roundtrips, failed writes, local/world rotation, orbit and picking failure paths through controlled native callbacks. They do not replace visual camera/viewport or live Jolt scene acceptance.

## Script gizmos

Both C# (`Funke.Graphics.Gizmo`) and C++ (`Funke::Gizmo`, `Graphics/Gizmo.hpp`) support world-space 3D debug shapes:

```csharp
Gizmo.DrawLine(new Vector3(0, 0, 0), new Vector3(0, 2, -3));
Gizmo.DrawBox(new Vector3(0, 1, -3), new Vector3(2, 2, 2), new Vector3(0, 45, 0));
Gizmo.DrawSphere(new Vector3(3, 1, -3), 1.0f); // optional segments = 32
```

```cpp
Gizmo::DrawLine(Vec3(0, 0, 0), Vec3(0, 2, -3));
Gizmo::DrawBox(Vec3(0, 1, -3), Vec3(2, 2, 2), Vec3(0, 45, 0));
Gizmo::DrawSphere(Vec3(3, 1, -3), 1.0f);
```

`DrawBox` draws the 12 edges of a box with the specified **full size**, rotated around its center. Rotation is optional (zero by default) and uses the same Euler-degree convention as `Transform3D`. `DrawSphere` draws three perpendicular great circles; segments per circle are clamped to at least 3. Nonpositive radii and nonfinite coordinates draw nothing. C# also provides `DrawLine(start, direction, distance)` for `Vector3`, normalizing the direction; a zero direction draws nothing.

These are wireframes, depth-tested against scene meshes, with the current gizmo color. Lines are one pixel wide. Submit them each frame (for example in `OnUpdate` or `OnPreRender`). They honor `Gizmo.IsEnabled` / `Gizmo::SetEnabled`, the editor view's Gizmos toggle, and the runtime gizmo visibility setting. Commands are retained for paused/resize refreshes and independently rendered into each 3D view.

The 3D per-view budget uses `MaxVertices` / `SetMaxVertices`: a line costs 1, a box 12, and a sphere `3 * segments`. Frustum-culled lines consume no budget; remaining lines are kept in submission order. This budget is separate from the 2D overlay budget. Extreme accumulation is rejected by the shared gizmo memory guard.

### Wavefront material libraries

OBJ import preserves consecutive `usemtl` face ranges. Unique `newmtl` names supply stable material keys across library reordering. `Kd`, `Ke`, `d`, `Tr` and plain `map_Kd` specify diffuse color, emission, opacity, inverse opacity and diffuse texture. `Ns` maps to roughness as `sqrt(2 / (max(Ns, 0) + 2))`. Other directives and map options produce warnings. Relative paths may contain spaces and resolve from their declaring file within the model directory. Missing libraries or images fail the load and remain tracked for reload. Asset pruning follows the OBJ to its libraries and diffuse maps. Windows Release tests covered three material runs, reordered definitions, texture decoding, missing and escaping dependencies, and the export retention plan. A Windows Development export made with a matching CLI and engine kept the referenced OBJ, its MTL and the diffuse PNG byte-for-byte and stripped an unreferenced PNG alongside them.

### Cached transform directions in C sharp

`Transform3D.Right`, `Up` and `Forward` read normalized columns of the last propagated world matrix (+X, +Y and −Z). A mirrored parent affects these directions. A zero-length column has the same undefined normalization as native `Forward`. For current rotation-only directions use `WorldRotation * Vector3.Right`, `Up` or `Forward`. The existing managed world-pose path reads current local transforms and leaves interpolation and the render cache intact. The scoped managed suite exercised hierarchy edits, singular transforms and cached direction access.

### Controlling the camera follow rig from C sharp

Use `GetComponent<CameraFollowRig>()` on the camera entity. `Target` accepts another live entity in the same scene or `null`. `Offset`, `Damping`, `Orbit`, `Yaw`, `Pitch`, `Distance` and `LookAtTarget` update the native component. Angles are in degrees. Call `Reset()` to snap to the desired position on the next follow update. A Windows Play fixture verified offset following, orbit positioning, reset, target clearing, self-target rejection and mirrored cached transform axes with the matched ScriptCore and engine (interop layout 61). The system uses the existing post-hierarchy follow phase. Obstacle avoidance requires a future sphere-cast query.
